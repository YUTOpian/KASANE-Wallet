# 共通・設定

## KASANE デザイン統一 (v12)

全画面を KASANE デザインに統一しました。Symbol / NEM のどちらを選んでいるかで、同じ KASANE デザインの「色味」だけが変わります。

| | Symbol | NEM |
|---|---|---|
| グラデーション | coral → pink → lavender | lavender → aqua → mint |
| ステージ背景 | くすんだ紫グレー (#2B262D) | くすんだ青緑グレー (#232A29) |
| アクセント(ダーク) | pink #E58AAE | aqua #7ED1C0 |

共通: 文字は KASANE ワードマークの淡い黄緑、グラデーション上の文字はインク色 (#262129)、細い字のタイトル、丸いボタン。

### 仕組み
- `src/theme/kasaneTheme.ts` … `createKasaneTheme(mode, chain)` が全画面のテーマ。`useTheme().kasane` で、グラデーション・ステージ背景・メニュー色などのトークンを取れる。
- `src/main.tsx` … ストアの `themeMode`(ダーク/ライト)と `chain` からテーマを作る。
- `src/theme/designScope.ts` … 画面グループごとにデザインを**固定**する。welcome → プロファイル → 新規作成/インポート → ニーモニック表示 → 完了、およびプロファイル設定・バックアップ・パスワード入力の画面は、ロゴ全体のグラデーション（coral→pink→lavender→aqua→mint）の**中立の配色**で、Symbol / NEM どちらの色味も付かない（保存済みチェーン・タイルの選択に影響されない）。ダーク/ホワイト/ビジネスの設定はこのグループにも効き、タイトル画面（GET STARTED の下の言語ボタン・テーマボタン）とプロファイル選択画面（右上、オフライントランザクションの左）から切り替えられる。プロファイル選択画面の左上の矢印でタイトル画面へ戻れる。それ以外は、Symbol 画面は常に Symbol 色、NEM 画面は常に NEM 色（サイドメニューで選んだチェーンで決まる）。ダーク/ライトの設定は Symbol / NEM 画面にも効く。
- `KasaneStage` … メニューなし画面の枠。上記の固定ルールに従う。
- 旧 `raccoonTheme.ts` と `lib/chainColors.ts` は廃止。

### 動作の変更点
- 初期のテーマは「ダーク」(KASANE本来の見た目)。保存済みの旧データも、更新後の最初の起動で一度だけダークに切り替わる(その後は設定 > テーマの選択が保たれる)。
- ライトテーマも KASANE の配色（淡いクリーム/ミントのステージ）で用意。
- 「さくら」テーマ（4つ目・女性向け）: 小さな花・ハート・きらきらを散らしたクリームピンクのステージ、明るいパステルのピンク→ライラックのグラデーション、角の大きい丸みのあるカード、ピンクの細い線とやわらかいピンクの影、丸ゴシック系フォント、淡いパステルの残高カード（暗い文字・白い花柄）、淡いピンクのサイドメニューと、選択中の項目をキャンディ色の丸いピルにして白文字にする（`menu.activeText`）。花などの柄の色もチェーンごとに変わる（`petalPattern`）。Symbol=ローズ系 / NEM=ミント系 / mijin=スカイブルー系と、チェーンごとに色味が変わる（`kasaneTheme.ts` の `BLOSSOM`）。ビジネステーマも同様に、ステージ・差し色・残高カード・サイドメニューがチェーンごとに色づく（`BUSINESS`）。設定 > テーマ、タイトル画面、プロファイル選択画面から選べる。
- インポート / ログイン系の画面(名前・完了・パスワード必須)も KASANE の枠に変更。
- 「エクスプローラーで見る」などのボタンは、個別の色指定をやめて KASANE グラデーションのボタンに統一。

NEMonster の絵(`nemonster.css`)と紙ウォレットの出力(`paperWallet.ts`)は、作品・印刷物なのでそのまま。

### NEM 画面を Symbol 側の UI に統一 (v97)
- モザイク / ネームスペース: 上部タブ＋一覧テーブル（スマホはカード）。NEM は「作成したモザイク｜モザイク作成」「保有ネームスペース｜ネームスペース作成｜サブネームスペース作成｜ネームスペースの更新」（更新は→「ネームスペースの更新 (NEM)」）。作成フォームはタブの下に埋め込み（`embedded`）。`/mosaic/create`・`/namespace/register` は同じ画面の作成タブを開く。期限切れの表示切替・並べ替え・再読み込みも Symbol と同じ。

- ハーベスト: 上に「状況＋残高」カード、その下にタブ付きカード（リモート有効化 / ノードに任せる / 状態）。

### サービス (NEM)
サイドメニューの「スーパーノードプログラム」「NEMonster」「投票」を「サービス」(`/service`) に集約。画面内に3つをタイル（`ChoiceCard`）で並べ、各画面には「戻る」でサービスへ戻れる。Symbol では「NEMonster」だけを出す（KASANE 独自の Symbol 版。mijin・閲覧用では非表示）。

## カスタムテーマ

設定 > テーマ に「カスタムテーマの設定…」があり、ひな形のCSSをダウンロード → 編集 → アップロードで、好きな見た目にできます。**カスタムテーマは10個まで保存でき**、保存したテーマは名前つきで、設定のテーマ一覧・スタート画面・プロファイル選択のテーマ切り替えに、ダーク／ホワイト／ビジネス／さくらと並んで出ます（選ぶだけで切り替わります）。

### 使い方
1. 「ひな形（ダーク）をダウンロード」。ひな形は**ダークだけ**で、選べません（標準のKASANEの見た目の値がそのまま書かれ、各項目にコメント（日本語・英語）が付きます）。
2. テキストエディタで `--kasane-` で始まる値を書き換えます。
3. 「CSSをアップロード」→ 読み込めた設定の数と、読み込まれなかった項目（行番号つき）が出る →
   - 「新しいテーマとして保存して使う」: 新しく保存します。上の「新しいテーマの名前」の欄に、好きな名前を付けられます（40文字まで。はじめはファイル名が入っています）。10個あるときは押せません（使っていないテーマを削除してください）。
   - 「『（選んでいるテーマ）』を置き換える」: いま選んでいるテーマの色などを、アップロードしたもので置き換えます（名前はそのまま。画像は下の決まりのとおり）。

### 保存したテーマ（一覧）
ダイアログの上に、保存したテーマが並びます。1つごとに「使う」（使用中のものには「使用中」の印）、名前を変える（鉛筆ボタン。いつでも変えられます）、このテーマのCSSをダウンロード、削除（確認あり）。
- 「このテーマのCSSをダウンロード」は、**設定してある値だけ**を書き出します（書いていない項目の標準の色を、別のチェーンの色として固定してしまわないため）。画像と、チェーンごとの上書き（`:root[data-chain='nem'] { … }`）も含み、そのままアップロードし直すと同じテーマに戻ります。
- 削除したテーマが選ばれていたら、残っているテーマの先頭が選ばれます。1つも残らなければ、ダークに戻ります。
- 前の版（1つだけ保存）で保存していたテーマは、一覧の1つ目として引き継がれます。
- 保存はこの端末のブラウザの中だけです。画像は、10個の合計で約320万文字（1つのテーマは約160万文字）までです。

### 変えられる項目（`--kasane-xxx`）
`mode`（dark / light。文字・入力欄・影などの標準の色が切り替わる）、`bg`・`glow`・`paper`、`text`・`text-soft`、`accent`、`primary`、`wordmark`、`gradient-start/mid/end`・`on-gradient`、`hero-start/mid/end`・`hero-text`、`menu-top/bottom/text`、`line`、`error`・`success`・`warning`・`info`、`radius`（0〜48）、`button-radius`（0〜999）、`font`、`background-dim`・`hero-dim`（0〜1。画像の上に重ねるこさ）。書かなかった項目は、`mode` に合わせた標準の色になります。
- チェーンごとに変える: `:root[data-chain='nem'] { --kasane-accent: #23917c; }`（symbol / nem / mijin / base。base はスタート画面・プロファイル選択など、チェーンに属さない画面）。`mode` は `:root` だけ。

### 画像（ロゴ・サイドメニューのアイコン・背景・残高カード）
「カスタムテーマの設定…」の「画像」の欄で、ファイルを選ぶだけで差し替えられます（PNG・JPEG・WebP・GIF・SVG）。画像は、いま選んでいるテーマに付きます（欄に、テーマの名前が出ます）。保存したテーマがないときは、1つ目の画像を選ぶと新しいテーマ（「カスタム 1」）が作られて、そのテーマに切り替わります。
- 差し替えられるもの（15か所）: ロゴの六角形のマーク（スタート画面・ダイアログ）／ロゴの「KASANE」の文字（スタート画面・サイドメニュー）／背景／残高カード／サイドメニューのアイコン11個（ホーム・アカウント・アドレス帳（現在は画面に出ない）・モザイク・ネームスペース・マルチシグ・ハーベスト・アグリゲート・サービス（NEM）・リンク集・設定）。
- 背景は、背景色を `--kasane-background-dim`（0〜1、既定 0.35）の濃さで重ねて、文字を読みやすくします。残高カードは、黒を `--kasane-hero-dim`（既定 0.3）の濃さで重ねます。
- 選んだ画像は、**ウォレットが描き直してから**保存します（canvas に描いて PNG / JPEG で出し直す）。大きさの上限は、アイコン96px・ロゴ640×560／文字1200×300・背景1600px・残高カード1200×900。上限より大きい画像は、縦横比を保って縮め、文字数の上限（アイコン6万・ロゴ30万・背景70万・残高カード50万。1つのテーマで合計160万、10個のテーマで合計320万）に収まるまで小さくします。ファイルは12MBまで。
- 画像はこの端末の中（ブラウザの保存領域）だけにあり、外には送りません。背景・残高カード以外の画像の位置・大きさは変えられません（ロゴは元と同じ枠に、縦横比を保って収まります）。
- CSSにも書けます: `:root { --kasane-image-nav-home: url("data:image/png;base64,..."); }`（名前は、ひな形のコメントに全部あります）。**`data:image/png|jpeg|webp;base64,` だけ**で、外のサイト（http:）の画像・SVG・gif は読み込みません。書いた画像も、同じように描き直してから保存します。`none` と書くと、その画像を消します。CSSに書いていない画像は、いま保存してある画像のままです。画像は `:root` にだけ書けます（チェーンごとには変えられません）。
- 「このテーマのCSSをダウンロード」で、画像も含めて書き出せます（CSSが大きくなります）。

### 安全のための決まり
アップロードしたCSSは、そのままページに入れません。ウォレットの画面は、見た目を変えるだけのCSSでも、ボタンの位置や表示を入れ替えれば利用者を騙すのに使えてしまうためです。
- 読み込むのは上の変数だけ。セレクタは `:root` と `:root[data-chain='…']` だけで、`@import`・`@media`・ほかのプロパティ・未対応の変数は読み飛ばし、画面に理由と行番号を出します。`url()` は、画像の変数に書いた `data:image/png|jpeg|webp` だけです（外のサイトの画像は読み込みません。ページの外に通信が起きないようにするためです）。
- 値は1つずつ検証して、決まった形に直してから保存します。色は `#hex`・`rgb()/rgba()`・`hsl()/hsla()`・white / black / transparent だけ（`#rrggbb` か `rgba(…)` に直す）。数値は範囲内だけ。フォントは名前（文字・数字・空白・`-` `_` `.`）の一覧だけで、括弧・`;`・`{}`・`\` などは不可。CSSファイルは3MBまで（画像を含むため）。
- 画像は、読み込んだファイルの中身をそのまま使わず、描き直した結果だけを保存します（SVG のスクリプト・画像のふりをしたファイル・EXIF などは残りません）。保存する形式は png / jpeg の data: だけで、アプリを開くときにもう一度、形式と長さを検証します。
- 保存したデータは、アプリを開くときにもう一度検証します（壊れた値・手で書き換えた値は捨てる）。有効な値がなければ、ダークに戻ります。
- 背景の花びらなどの飾りやレイアウトは、カスタムテーマでは変えられません（さくらの花びらの模様は、カスタムでは出ません）。画像の差し替えで、ボタンの位置や文字は変わりません。

## テストXYM / テストXEM の返還（設定）

テストネットのときだけ、設定に「テストXYMを返還」（Symbol）／「テストXEMを返還」（NEM）が出る（閲覧用プロファイルでは出さない。いまのチェーンの方だけ出る）。

- 返還先（固定）: テストXYM `TCNQVX-TIQIDQ-OGTYW6-HLZ5TL-JALE2B-O6VMIA-HUA`／テストXEM `TCSMSA-MGFNWZ-VWFTJ3-4GKIZK-YQNDJO-VICWIR-MVQY`。送る直前に、チェックサムとテストネット（0x98）であることを確かめ、メインネットでは動かさない。
- 操作: タイルを開く → 返還先・残高・手数料・返還額を確認 → 「全額返還する」→ パスワード（Ledger はデバイスで承認）。1回の送金で、残高から手数料を引いた全額を送る。
- 返還額の計算: Symbol は、送金の最大手数料（手数料の既定値の速さ）を引く。NEM は、手数料が金額で決まるので、全残高にかかる手数料を引く。送る直前にもう一度計算し直す。実際の手数料が見積りより低いときは、ごくわずかな端数が残る。
- 実装: `src/lib/testnetReturn.ts`（返還先・計算・送金）／`src/components/TestnetReturnDialog.tsx`／`SettingsTop.tsx`／文言は `settings.testnet_return_*`（5言語）。

## 表示言語（5言語）/ Display languages

公式対応言語: 日本語 (`ja`)・English (`en`)・简体中文 (`zh`)・한국어 (`ko`)・Русский (`ru`)

### ファイル構成
- `src/i18n/languages.ts` … 言語一覧（自言語表記・ロケール・`<html lang>`）。言語を足す／並べ替えるときはここ。
- `src/i18n/messages.json` … `ja` と `en`（元の vue-i18n 由来）。
- `src/i18n/zh.json` / `ko.json` / `ru.json` … 追加3言語。キー構造は `messages.json` の `en` と同じ。
- `src/i18n/index.ts` … 登録。未翻訳キーは **English → 日本語** の順にフォールバックする（生のキー名は表示されない）。

### 翻訳状況
`zh` / `ko` / `ru` は `en` と同じ全キーを翻訳済み。
新しい文言を `messages.json` に足したら、`zh.json` / `ko.json` / `ru.json` にも同じキーを追加する
（追加し忘れた分は English で表示される）。

### 翻訳を追加するとき
- `en` の同じキー・同じ階層に追加する。`{{count}}` などのプレースホルダは変更しない。配列（複数段落）は要素数を揃える。
- 簡体字中国語は用語を統一: 收割(harvest) / 重要性(importance) / 马赛克(mosaic) / 命名空间(namespace) / 多重签名(multisig) / 区块(block) / 节点(node)。

## マイリンク（リンク集のカスタマイズ）

リンク集（About画面）の「マイリンク」で、好きなサイトやツールのリンクを追加・編集・削除できます。

- 追加: 「リンクを追加」タイル → 名前（空欄なら サイト名）と URL を入力。`nemscan.io` のように https:// を省いても可。
- 編集・削除: タイル右上の鉛筆アイコン → ダイアログの「削除」。
- 保存先: この端末のブラウザ（localStorage `kasane-custom-links`）だけ。ネットワークには送りません。
- 追加する場所: 追加・編集ダイアログで「両方」「Symbolのみ」「NEMのみ」から選びます（初期値はいま選んでいるチェーン）。いま選んでいるチェーンに追加したリンクだけが表示されます。上限はチェーンごとに50件（「両方」は両チェーンに数えます）。
- 以前（v1）の保存データは、それぞれのチェーンのみに置いたリンクとして自動で引き継がれます。
- 使えるのは http / https のみ（`javascript:` などは拒否）。

実装: `lib/customLinks.ts`（URLの整形・検証）、`store/customLinksStore.ts`、`components/CustomLinkDialog.tsx`、`components/LinkList.tsx`。

## 診断コンソール(ログ表示)

設定 > 「診断コンソール」(Symbol/NEM どちらでも)。`/settings/diagnostics`

### 記録されるもの
- ノードとの通信(`node` / `nem-node`): 使ったノード、パス、応答時間、失敗の理由・再試行(成功は「詳細」レベル)
- ノードの選択・接続テスト・自動切替(Symbolノード管理と連動)
- 送信(`tx`): アナウンスしたトランザクションのハッシュ、拒否された理由
- `console.*` の出力と、捕まえられなかったエラー・未処理のPromiseエラー(`console` / `window`)
- 「接続を確認」ボタンの結果(使うノード → 接続テスト → チェーンの高さ)

### 画面
- 表示レベル(プルダウン): すべて(詳細含む)/情報以上/警告以上/エラーのみ
- 絞り込み(ソースとメッセージ)、最新を追う、コピー、ファイルに保存(環境情報つき)、消去

### 安全面
- ログはメモリ上のみ(最大500件)。端末に保存せず、どこにも送信しません。再読み込みで消えます。
- すべての行を `redact()` で通します: 64桁以上の16進(鍵・ハッシュ)は、直前が hash / publicKey / signer のときだけ残して他は伏せる、12語以上続く英小文字の語(ニーモニックフレーズ)、`password=` `privateKey:` など、オブジェクトの secret/password/mnemonic/seed/priv 系のキーを伏せます。
- 共有前に内容を確認するよう、画面に注意書きを出しています。アドレスやノードURLは含まれます。

### 実装
- `src/lib/diagnostics.ts`(記録・伏せ字・絞り込み・レポート)、`src/pages/settings/DiagnosticsPage.tsx`
- `src/main.tsx` で起動時に `installDiagnostics()`
- テスト: `npx tsx dev-tests/diagnostics.test.ts`(22項目)

## アドレス帳

連絡先の管理、ホワイトリスト / ブラックリスト、送金後の保存ポップアップ。左メニューの「アカウント」画面の、左のカードの見出し「マイアカウント | マイ連絡先」の切り替え（`/account?tab=addressbook`。公式のSymbolウォレットと同じ作り）から開く（以前は独立したメニュー。古い `/addressbook` のアドレスは、このタブを開く）。署名が要らないので、閲覧用プロファイルでも使える。

### 連絡先

- 項目：名前・アドレス・メールアドレス・電話番号・メモ・区分（ホワイトリスト / ブラックリスト。必ずどちらかに入り、新規はホワイトリストが初期値）。以前の「通常」の連絡先は、読み込み時にホワイトリストへ移す。
- アドレスは Symbol / NEM のどちらでもよい（`parseWatchAddress` がチェーン・ネットワークを判定する）。同じチェーン・ネットワーク・アドレスの重複は登録できない。
- 名前は必須。ただしブラックリストだけは名前なしで登録できる（見知らぬ相手をブロックするため）。
- 一覧は、いま選んでいるチェーン・ネットワークの連絡先だけを表示する（別のチェーンには送れないため）。検索と、ホワイトリスト / ブラックリストのタブがある。
- 保存先は、ウォレットと同じ localForage（キー `ADDRESS_BOOK`）。端末のブラウザにだけ保存され、外部へは送らない。プロファイルを切り替えても同じアドレス帳を使う。

- 詳細にアドレスのコピーボタンがある。
- 画面の作り：公式のSymbolウォレットの「マイ連絡先」に合わせる。広い画面（900px〜）は、左に一覧（ホワイトリスト / ブラックリストのタブ・検索、下に「連絡先を追加」「アドレス帳をインポート」「バックアップ」）、右に選んだ連絡先の詳細（送金・編集・削除）。狭い画面は一覧だけで、連絡先を押すと詳細がダイアログで開く。送金先を選ぶとき（`&pick=1`）はタブを出さず一覧だけで、上に「戻る」があり、押した連絡先がそのまま送金先になる。
  スーパーノードプログラム・アポスティーユ・署名付きメッセージ（NEM）も同じく、幅の上限を外して画面いっぱいに使う（登録 / 作成の画面は広い画面で2カラム）。

### バックアップ / インポート（JSON）

- 画面右上のメニューから。バックアップはアドレス帳の全件（別チェーンのものも含む）を `kasane-address-book-YYYY-MM-DD.json` として保存する。**暗号化はしない**ので、メールアドレス・電話番号の扱いに注意。
- 形式：`{ "format": "kasane-address-book", "version": 1, "exportedAt": "...", "entries": [{ chain, network, address, name, email, phone, memo, list, createdAt, updatedAt }] }`。
- インポートは、読めない行を数えて除き、制御文字と長さを整えてから取り込む。モードは「追加・更新」（同じアドレスは取り込んだ内容で更新、残りは残す）と「すべて置き換える」。

### 要注意 / 信頼

※ 画面・文言では、アカウント制限の「許可リスト／ブロックリスト」と区別するため、アドレス帳の区分を「信頼」「要注意」と呼ぶ（内部の値は従来どおり `white` / `black`）。

- **履歴**：要注意のアドレスから来た取引（自分が署名したものは除く）を、Symbol / NEM どちらの履歴でも隠す。要注意のタブにあるスイッチでオフにできる。履歴の下の「表示する」で、その画面でだけ一時的に見せることもできる。CSV には、いま見えている行だけが出る。
- **署名依頼**：署名待ち（マルチシグ画面）・署名QR画面・オフライン連署・取引の詳細（署名待ち）で、依頼を送ってきたアドレスを調べる。
  - アドレス帳に無い（自分のアカウントでもない）→ 警告（「アドレス帳に追加」ボタン付き）。署名待ちの一覧には印も付く。
  - ブラックリスト → 強い警告。署名ボタンを押すと確認ダイアログが出る。
  - 連絡先 / 信頼 → 名前を表示。自分のアカウントからの依頼には何も出さない。
- **送金**：送金フォームで連絡先なら名前を表示。要注意の相手なら警告（送金確認画面にも出る）。アドレス帳の画面から要注意の相手を選ぶときも確認する。
- 自分のアカウントのアドレスをうっかりブロックしても、自分の取引・署名依頼は隠さない・警告しない。

### 送金後の「新しいアドレスを保存しますか」

送金が通ったあと、相手がアドレス帳にも自分のアカウントにも無ければ、名前を入れて保存するポップアップを出す（そのあとで Home に戻る）。「このアドレスについては今後たずねない」にすると、そのアドレスでは出さない。QRに書き出す送金（署名のみ）では出さない。

### 送金先をアドレス帳から選ぶ

送金フォームのアドレス欄の横の連絡先ボタン → `/account?tab=addressbook&pick=1`。連絡先を選ぶと、送金先に入れて Home の送金欄に戻る。

### 変更したファイル

- 追加：`src/lib/addressBook.ts`（検証・バックアップ・マージ・信頼度の判定。純粋な処理）、`src/store/addressBookStore.ts`、`src/hooks/useAddressBook.ts`、`src/lib/signerTrust.ts`、`src/pages/addressbook/AddressBookPanel.tsx`（「アカウント」画面のタブ。`AccountPage.tsx` が包む）、`src/components/{ContactDialog,SaveContactDialog,SignerTrustNotice,BlockedSignerDialog}.tsx`、`dev-tests/address-book.test.ts`

## 閲覧用プロファイル（アドレスだけで見る）

新規プロファイルの選択肢は「新規作成」「インポート」「閲覧用」の3つ。閲覧用はアドレスを入力するだけで、
残高・保有モザイク・取引履歴などを見られる。**秘密鍵・公開鍵・ニーモニック・パスワードは一切保存しない。**
Symbol と NEM で共通。

### 作り方
- 新規プロファイル →「閲覧用」（`/wallet/watch`、`pages/wallet/WalletWatchNew.tsx`）
- アドレスを入力すると、**チェーンは長さ（Symbol 39文字 / NEM 40文字）、ネットワークは先頭の文字（N=メインネット / T=テストネット）で自動判定**（`lib/watchAddress.ts`）。ハイフン・小文字・空白は無視。チェックサムも確認する。
- プロファイル名を付けて作成すると、そのアドレスのチェーン・ネットワークで Home が開く。
- 1つの閲覧用プロファイルに、Symbol と NEM のアドレスを何件でも追加できる（メニュー「アカウント」→「閲覧用アドレスを追加」、
  または、そのチェーンのアドレスがまだ無いときに Home に出る案内から）。同じアカウントなら別ネットワークの表記でも重複として弾く。

### ネットワークの扱い
アドレスは「ネットワークバイト＋公開鍵のハッシュ＋チェックサム」なので、メインネット⇔テストネットの違いはネットワークバイトとチェックサムだけ。
そこで閲覧用アカウントは入力されたアドレスを保存し、`Wallet.address` が**今選んでいるネットワークのアドレスへ変換して返す**
（`convertAddressNetwork` / `convertNemAddressNetwork`）。通常のプロファイルと同じく、設定でネットワークを切り替えられる。

### 隠す機能（鍵が要るもの）
| 場所 | 閲覧用での扱い |
| --- | --- |
| メニュー | メタデータ・マルチシグ・アグリゲート・署名QR・ハーベスト・スーパーノード・NEMonster・投票を出さない |
| Home | 「送る」リボンとハーベスト設定へのリンクを出さない（保有モザイク・インボイス・取引履歴・ハーベスト履歴は使える） |
| アカウント | 秘密鍵・公開鍵・メタデータ追加/編集・「アカウントを追加」・バックアップを出さない。アドレス・QR・残高・インポータンス・エイリアスは見られる |
| モザイク / ネームスペース | 一覧は見られる。作成・登録・メタデータ追加を出さない |
| 取引の詳細 | 暗号化メッセージの復号ボタンを出さない |
| プロファイルの設定 | 名前の変更・削除だけ（バックアップ・パスワード変更は出さない） |
| 設定 | 秘密鍵のバックアップを出さない |

URL を直接開かれても、鍵が要る画面（`/send/confirmation`・`/mosaic/create`・`/namespace/register`・`/metadata`・`/multisig*`・
`/aggregate`・`/signqr`・`/harvest`・`/supernode`・`/nemonster`・`/voting*`・`/wallet/backup*`）は `router.tsx` の `KeyRequired` で Home に戻す。
パスワードが無いことを検出する `PasswordExposureGuard` は、閲覧用プロファイルを対象外にしている。

### 実装
- `lib/storage.ts`: `Wallet.watchOnly` / `Wallet.watchAddress`、`WalletsHelper.addWatchProfile` / `addWatchAddressToProfile` / `isActiveWatchOnly`
- `hooks/useWatchOnly.ts`: いま使っているプロファイルが閲覧用かを返す（画面の出し分けに使う）
- `components/WatchAddressDialog.tsx`、`pages/top/WatchAddressEmpty.tsx`: アドレスの追加
- i18n: `watch.*`（日本語・英語）
- テスト: `dev-tests/watch-address.test.ts`（判定と変換）、`dev-tests/watch-profile.test.ts`（保存・切り替え・削除）。`npx tsx dev-tests/<file>` で実行

## キーストア（秘密鍵・公開鍵ファイル）

アカウントの**秘密鍵と公開鍵（アドレス付き）**を JSON ファイルとしてダウンロードできます。
ファイルはすべて端末の中で作られます（アップロードも保存もしません）。

### どこから作れるか
ウォレット設定 → バックアップ（秘密鍵表示、`/wallet/backup`）の「キーストアをダウンロード」。
秘密鍵を画面に表示できた後にだけボタンが出ます。Symbol / NEM どちらのアカウントでも使えます。

### 2種類のファイル
| | 暗号化（既定・推奨） | 平文 |
|---|---|---|
| format | `kasane-keystore` | `kasane-keypair` |
| 秘密鍵 | パスワードで暗号化 | そのまま 16進で記載 |
| 公開鍵・アドレス | そのまま読める | そのまま読める |
| 注意 | パスワードを忘れると取り出せない | 持っている人は誰でも資産を動かせる（画面に警告を出す） |

パスワードは、キーストア専用のもの（8文字以上・確認入力あり）で、ウォレットのパスワードとは別です。

### 暗号化の方式（`src/lib/keystore.ts`）
- 鍵の伸長: scrypt（N=2^15, r=8, p=1, 32バイト、ソルト16バイト）
- 暗号: AES-256-GCM（ノンス12バイト）。chain / network / address を認証付き追加データに含めるので、ファイルの住所を書き換えるとパスワードチェックに失敗します
- 読み込み側（`readKeystore`）は scrypt の N が大きすぎるファイルを拒否します

```json
{
  "format": "kasane-keystore", "version": 1,
  "chain": "symbol", "network": "mainnet",
  "address": "N...", "publicKey": "…64桁…",
  "crypto": { "cipher": "aes-256-gcm", "ciphertext": "…", "nonce": "…",
              "kdf": "scrypt", "kdfparams": { "n": 32768, "r": 8, "p": 1, "dklen": 32, "salt": "…" } },
  "createdAt": "2026-10-11T00:00:00.000Z"
}
```

### ファイル
- `src/lib/keystore.ts` … 作成・読み込み（純粋関数）
- `src/components/KeystoreButton.tsx` … ボタンとパスワード入力ダイアログ
- `src/pages/wallet/WalletBackup.tsx` … 秘密鍵表示にボタンを設置
- `src/lib/paperWalletExport.ts` … `saveFile` に MIME 引数を追加（iOS は共有シート）
- `src/i18n/messages.json` … `wallet.keystore_*`（日本語・英語）
- `dev-tests/keystore.test.ts` … `npx tsx dev-tests/keystore.test.ts`

### 未実装
キーストアファイルの**読み込み（インポート）画面**。`readKeystore()` は用意してあるので、インポート画面から呼べます。

NEM公式ウォレットの形式（.wlt）の書き出し・読み込みは別機能です。→ 本書「ウォレットファイル（.wlt）」

## ペーパーウォレット

Symbol 公式デスクトップウォレット（1.2.0）にあるペーパーウォレットと同じ内容を、**KASANE デザイン**の PDF（A4・1枚）で作ってダウンロードできます。
PDF はすべて端末の中で作られます（アップロードも保存もしません）。

### どこから作れるか
| 画面 | 内容 |
|---|---|
| ニーモニック生成直後（`/wallet/creation/mnemonic`） | ニーモニックフレーズのペーパーウォレット |
| 設定 → バックアップ（ニーモニックフレーズ表示） | 同上 |
| ウォレット設定 → バックアップ（秘密鍵表示） | その口座の秘密鍵のペーパーウォレット |

ボタンは、フレーズ／秘密鍵を画面に表示できた後にだけ出ます。

### 載る内容
| | Symbol | NEM |
|---|---|---|
| フレーズ（12/24語、番号付き） | ○ | ○ |
| 秘密のQR | フレーズ QR（type 5）／ 秘密鍵 QR（type 2） | なし（NEM に標準の QR 規格がないため） |
| 公開QR | コンタクト QR（type 1：名前＋公開鍵） | NEM アドレス QR（v2 / type 1） |
| アドレス・公開鍵・ネットワーク・導出パス | ○ | ○ |

- Symbol の QR は公式ライブラリ（symbol-qr-library、公式デスクトップウォレット 1.2.0 同梱版）の JSON 形式（`v:3`、`type`、`network_id`、`chain_id`、`data`）に合わせています。暗号化はしていません（公式のペーパーウォレットと同じ）。
- フレーズのシートは、いま選んでいるチェーン（Symbol / NEM）のルートアカウント（インデックス 0）の情報を載せます。
- ネットワーク（メインネット／テストネット）はヘッダーのバッジに出ます。

### 作り方（公式との違い）
公式は PDF テンプレートに文字を重ねる方式ですが、KASANE ではテンプレートなしで、`pdf-lib` で直接描いています。

- 文字は PDF 標準フォント（Helvetica / Courier）だけを使うので、フォントの同梱が要りません（載る文字はすべて ASCII）。
- ロゴ（ヘキサゴンと五重塔）は `src/assets/kasane_mark.png`（アプリ内の SVG と同じ絵を PNG にしたもの）、ワードマークはベクターで描画。
- QR は `qrcode.react` の `QRCodeCanvas` を画面外に描いて PNG にして埋め込みます。描けていない（真っ白）場合は、白い QR を印刷してしまわないよう、エラーにして止めます。
- iOS（特にホーム画面アプリ）では `<a download>` が効かないため、共有シート（Web Share API）で渡します。

### ファイル
- `src/lib/paperWallet.ts` … PDF のレイアウト（純粋関数。アプリの状態に依存しない）
- `src/lib/paperWalletExport.ts` … 鍵の導出、QR の中身と画像化、ダウンロード
- `src/components/PaperWalletButton.tsx` … ボタン（作成中表示・失敗表示つき）
- `src/pages/wallet/WalletCreationMnemonic.tsx` / `WalletBackup.tsx` … ボタンの設置
- `src/i18n/messages.json` … `wallet.paper_wallet_*`（日本語・英語）
- `src/assets/kasane_mark.png` … ロゴ
- `dev-tests/paper-wallet.test.ts` … 単体テスト（`npx tsx dev-tests/paper-wallet.test.ts`）

### 依存の追加
`package.json` に `pdf-lib`（^1.17.1）を追加しました。**`npm install` を一度実行してください**（`package-lock.json` はまだ更新していません）。

### 未対応
- ペーパーウォレットの PDF に載せる QR のパスワード暗号化（PDF の QR はいまも平文）。暗号化 QR はバックアップ画面から別に作る（下記）。
- 複数インデックスのアカウントをまとめて印刷すること（いまはルート＝インデックス 0 と、画面に出ている 1 口座分）。

### パスワード付きニーモニックQR（公式ウォレット互換）
- バックアップ（ニーモニック表示）の「パスワード付きQRを作る」で、QR 用のパスワードを決めて暗号化 QR を作る（表示・文字列コピー・PNG 保存）。`lib/symbol/mnemonicQr.ts`、`components/MnemonicQrExport.tsx`。
- インポート画面の QR 読み取り（カメラ／画像）で、type 5 の QR を読む。暗号化なら `MnemonicQrPasswordDialog` でパスワードを聞いて復号し、24 語の欄に入れる。平文の QR（ペーパーウォレット）と単語の羅列も読める。
- 形式は Symbol QR v3 の type 5（`data.ciphertext` / `data.salt`）。暗号は AES-256-CBC + PBKDF2（CryptoJS）。**公式ライブラリの正確なパラメータ（ハッシュ・反復回数・IV の持たせ方）は `mnemonicQr.ts` の `VARIANTS` に並べてある。** 作るときは先頭、読むときは全部を試し、BIP39 として正しい結果が出たものだけを採用する。公式ウォレットの実物の QR で確認し、確定したら候補を絞ること。

## Symbol公式ウォレットのプロファイルとの互換（読み込み・書き出し）

Symbol 公式デスクトップウォレット（symbol-desktop-wallet 1.2.0 のブラウザ版）のプロファイルと、KASANE のプロファイルを、お互いに持ち込めます。
データはすべて端末の中で処理され、アップロードも保存もしません。

### いちばん大事な注意：ブラウザのデータは、アドレスが違うと共有できません
公式ウォレットはプロファイルをブラウザの `localStorage` に持っています。ブラウザは **アドレス（ドメイン）ごとに** データを分けるので、
公式ウォレットと KASANE が別のアドレスで動いていると、KASANE から公式ウォレットのデータは直接は見えません（逆も同じ）。
そのため、データは「貼り付け」か「ファイル」で受け渡します。同じアドレスで動かしている場合だけ、「このブラウザから探す」で直接読めます。

### 同じアドレスなら、起動時に自動で見つけます
公式ウォレットと KASANE が**同じアドレス（ドメイン）**で動いているブラウザでは、KASANE を開いたときに、公式ウォレットのプロファイルを自動で探します。
KASANE にまだ無いプロファイルが見つかると、「公式ウォレットのプロファイルが見つかりました」という画面が出ます。
**公式ウォレットのパスワードを入力して「開く」→ 内容を確認 →「読み込む」**だけで追加できます（貼り付けやファイルは要りません）。

- **パスワード無しで、完全に自動で追加することはできません。** 秘密鍵は公式ウォレットのパスワードで暗号化されているので、パスワード無しでは開けません（見つけるところまでが自動です。見つけるときに見るのは、パスワード無しで読める公開鍵だけです）。
- 画面の「キャンセル」はその回だけ、「今後は聞かない」はそのプロファイル（名前と最初の公開鍵の組）を、次から出さなくします。
- すでに KASANE にある鍵を含むプロファイルは、読み込み済みとみなして出しません。
- **アドレスが違うと見つけられません。** ブラウザはアドレスごとにデータを分けるので、別のアドレスで動いている公式ウォレットのデータは、KASANE から見えません。その場合は、次の「貼り付け」か「ファイル」で読み込んでください。

### KASANE から削除したあとも、また読み込めます
KASANE から読み込んだプロファイルを削除しても、ブラウザに公式ウォレットのプロファイルが残っている限り、また読み込めます。
「Symbol公式ウォレットのプロファイルを読み込む」を開くと、このブラウザにある（KASANE にまだ無い）プロファイルが上に出るので、選んでパスワードを入れるだけです。
「今後は聞かない」にしたプロファイルも、この画面には出ます（起動時の自動の確認だけが出なくなります）。
プロファイルの一部のアカウントだけを個別に削除した場合は、残りのアカウントが KASANE にあるので、重複を避けるため、そのプロファイルは読み込めません（プロファイルごと削除してください）。

### 公式 → KASANE（読み込み）
1. 「新しいプロファイルを追加」画面（作成・インポートの選択画面）の下にある「Symbol公式ウォレットのプロファイルを読み込む」を開く。
2. 公式ウォレットのデータを入れる。次のどれか：
   - **貼り付け**: 公式ウォレットを開いたタブで F12 → コンソールに、ダイアログに表示されているスクリプトを貼って実行すると、`profiles` と `accounts` がクリップボードにコピーされます。それをダイアログの入力欄に貼り付けます。
   - **ファイルを選ぶ**: 同じ内容の JSON（KASANE が書き出したファイルも読めます）。
   - **このブラウザから探す**: 公式ウォレットと同じアドレスで動いているときだけ。
3. プロファイルを選び、**公式ウォレットのパスワード**を入力して「開く」。
4. 内容（アカウント数・ニーモニックフレーズの有無・読み込めないアカウント）を確認して「読み込む」。

読み込みの内容：
- パスワードの確認は、公式と同じく SHA3-512 のハッシュの照合です。各アカウントの秘密鍵は、公式と同じ方式（PBKDF2-SHA1 1024回 + AES-256-CBC）で開き、**保存されている公開鍵と一致するか**も確かめます（一致しないものは読み込まず、理由を表示）。
- 公式のプロファイルにニーモニックフレーズ（`seed`）があり、アカウントが `m/44'/4343'/n'/0'/0'` から導出したものと一致すれば、KASANE でも**ふつうのニーモニックフレーズのプロファイル**になります（Symbol と NEM の 0〜9 を作り、公式にあったインデックスだけ表示。KASANE でバックアップとして表示も可）。
- それ以外のアカウント（秘密鍵で追加したもの・導出が一致しないもの）は、同じプロファイルの「秘密鍵のアカウント」として入ります。ニーモニックフレーズが無い／使えないプロファイルは、全部が秘密鍵のアカウントになります。
- **テストネット**：公式ウォレットのテストネットは `m/44'/1'/…`、KASANE は `m/44'/4343'/…` で導出が違います。KASANE では再導出できないので、ニーモニックフレーズは持ち込まず、秘密鍵のアカウントとして読み込みます。読み込んだあと、KASANE のネットワークを切り替えてください。
- 公式の既定名（「Seed Account 1」など）は、KASANE の「インデックス N」表示に任せます。自分で付けた名前は引き継ぎます。
- **読み込めないもの**：Trezor、Ledger のオプトインアカウント。Ledger のアカウント（メインネット）は、公開鍵とインデックスだけ持ち込みます。
- すでに KASANE にある鍵が含まれるときは、二重に作らないよう、何も読み込みません。
- KASANE のパスワードは、公式と同じものをそのまま使います（8文字以上・72バイト以下）。条件に合わないときだけ、新しいパスワードを決めます（秘密鍵はそのパスワードで暗号化し直します）。

### KASANE → 公式（書き出し）
1. 「ニーモニックフレーズ」画面（パスワード確認のあとにフレーズを表示する画面。秘密鍵だけのプロファイルでは、その旨の表示の下）にある「公式ウォレット用に書き出す」。
2. KASANE のパスワードを入力。書き出したデータは**同じパスワード**で暗号化され、公式ウォレットでも同じパスワードでログインできます。
3. 「ファイルに保存」または「コンソール用スクリプトをコピー」。スクリプトは、公式ウォレットを開いたタブのコンソール（F12）に貼って実行します。公式ウォレットの一覧に**追加**され（すでにあるプロファイルは消しません。同じ名前があれば追加しません）、ページが読み込み直されます。

書き出しの内容：
- 表示しているアカウント（非表示のアカウントは含めません）。メインネットでニーモニックフレーズがあるときは、公式の「ニーモニックから作ったプロファイル」と同じ形（`seed` + 導出パス、種類は SEED）。
- テストネット、またはニーモニックフレーズが無いプロファイルは、秘密鍵のアカウント（PRIVATE_KEY）として書き出します（導出が違うため）。Ledger はメインネットのみ書き出し、テストネットの Ledger は書き出せません。
- 保存形式の版数は、公式ウォレット 1.2.0 に合わせています（profiles = 8、accounts = 7）。別の版の公式ウォレットでは、データが移行される、または読めないことがあります。
- 書き出したデータには**暗号化された秘密鍵**が入っています。パスワードを知っている人は資産を動かせるので、ファイルやスクリプトを他の人に渡さないでください。

### 確認したこと・していないこと
- 確認済み：暗号（暗号文の形式と、公式ウォレットに同梱の crypto-js・SDK の `Crypto.encrypt` が作った暗号文を読めること／こちらが作った暗号文を公式のコードが読めること）。パスワードのハッシュ（SHA3-512）。公式の導出方式（SLIP-0010 ed25519・全階層ハードン・パスフレーズ空）が KASANE の `hd.ts` と同じであること（コードの突き合わせ）。
- テスト：`npx tsx dev-tests/official-profile.test.ts`（暗号・読み取り・読み込み・書き出し・往復）。
- まだ確認していないこと：実際の公式ウォレットの画面で、書き出したプロファイルでログインできること。書き出し／読み込みの画面を、実機のブラウザで通しで操作すること。

## Ledger（ハードウェアウォレット）対応 — 第1段階（v96: 公式の形式に合わせて修正・つなぎ方の表示を簡単に・作成画面をスタート画面と同じ見た目に）

秘密鍵をデバイスの外に出さずに使うための対応です。**この版では「プロファイルの作成」と「送金（Symbol / NEM）」まで**です。
それ以外の署名操作はまだ Ledger では使えません（下の「未対応」参照）。

### ★先に読んでください：実機での確認が必要です
v92 までは命令コード・データの並びを記憶に基づいて書いていましたが、**公式の実装（Symbol Desktop Wallet 1.2.0 の `Ledger.ts`、NEM Wallet の `hw-app-nem.js`）と照合して直しました**（`src/lib/ledger/apps.ts`）。
- 公開鍵の取得：データは「パス＋ネットワーク種別(1バイト)」。Symbol の応答は `[32][公開鍵]` だけ（アドレスは返らないので公開鍵から計算）。NEM の応答は `[40][アドレス][32][公開鍵]`（アドレスは計算値と照合）。
- 署名：P1 は「続きがある=0x80」「先頭ではない=0x01」（1回なら 0x00、3回なら 0x80 / 0x81 / 0x01）。P2 は Symbol も NEM も 0x80（Ed25519）。
- パス：メインネットは Symbol `m/44'/4343'/i'/0'/0'`、NEM `m/44'/43'/i'/0'/0'`。テストネットはどちらも `m/44'/1'/i'/0'/0'`。
- Symbol の署名対象は「ジェネレーションハッシュ ＋ トランザクションの 108 バイト目以降」（公式と同じ）。USB/HID のフレーム分割も公式の `hid-framing` と同じ。
- ただし**実機ではまだ試していません**。テスト（`dev-tests/ledger-apps.test.ts`）は、この並びを公式から読み取ったとおりに作っているかの確認で、本物のデバイスが受け付けるかの確認ではありません。
- 実機で動かなかったときは、**`PROTOCOL` と `getLedgerAccount` / `ledgerSign` だけを直せば済む**ように、通信の部品と分けてあります。
- 間違った形式のまま誤って署名・送信しないよう、自己検証を入れています。
  1. NEM は、デバイスが返したアドレスが、公開鍵から計算したアドレスと一致しなければ受け付けない。
  2. 署名の前に、デバイスのその番号の公開鍵が、このアカウントの公開鍵と同じかを確かめる（別の Ledger を繋いだときに止める）。
  3. 署名のあと、返ってきた署名を公開鍵で検算し、通らなければ送らない（`signWithLedger`）。
- 公式にあってまだ入れていないもの：アプリ版数の確認（INS 0x06）、連署（`signCosignatureTransaction`）。
- `npm install` ができなかったため、**`npm run build` と SDK を使うテストは実行していません**。最初に `npm install && npm run build` を通してください。

### できること
- 新規プロファイル →「Ledger」（`/wallet/ledger`）：チェーン（Symbol / NEM）と接続方法を選び、デバイスから公開鍵を5件（インデックス 0〜4）読んで登録。最初の1件だけ表示、残りは非表示。
  - 秘密鍵・ニーモニックフレーズ・パスワードは保存しません（`Wallet.ledger = true`、`encryptedSecret` は空）。
  - Symbol と NEM でデバイス側のアプリが違うので、1回に1チェーン。もう一方は別のプロファイルとして作ります。
- 送金（Symbol / NEM）：確認画面のボタンが「Ledger で署名して送る」になり、デバイスで承認して送信。署名済みトランザクションの QR 書き出しも同じ流れで使えます。
- つなぎ方：画面には「USB ケーブル」と「Bluetooth」だけを出します（使えるものだけ、前回成功した方を覚えます）。
  - 「USB ケーブル」の中で WebHID と WebUSB のどちらを使うかは自動で決めます（`openLink` / `openCable`、`transport.ts`）。WebHID を先に試し、**開けなかったとき**（Ledger Live など別のアプリが使っている等）だけ WebUSB を試します。Android は WebHID が無いので WebUSB だけです。
  - デバイスを選ぶ画面を**閉じた**ときは、そこで止めます（続けて別の選ぶ画面は出しません）。
  - 前回うまくいった方式は先頭に、開けなかった方式は後ろにして、次の回から試します（ブラウザの決まりで、選ぶ画面は押した直後にしか出せないため、2つ目の方式が出ないことがあります。そのときはもう一度ボタンを押すと、もう一方の方式から試します）。
  - 開けなかったときのメッセージは `ledger.error_in_use`（「Ledger Live など、ほかのアプリが使っていないか確認して…」）です。

### 使えない（案内を出す）もの
- **暗号化メッセージ**：送り手の秘密鍵が要るので、Ledger では作れません。確認画面で警告を出し、黙って平文にはしません。
- **iPhone の Safari**：WebHID / WebUSB / Web Bluetooth のどれも無いため接続できません（その旨を表示）。
- **WebHID は Android 非対応**（Android は WebUSB か Bluetooth）。

### 未対応（第2段階以降）
Ledger のアカウントでは、次の画面は開けません（メニューにも出さず、URL を直接開いても Home に戻ります）。
マルチシグ（作成・送信・連署）、アグリゲート、署名QR・オフライン署名、ハーベスト（キーリンク・投票鍵）、モザイク／ネームスペースの作成・供給量変更・エイリアス、
メタデータ、アカウント制限の編集、NEM のスーパーノード／NEMonster／投票、秘密鍵の表示・バックアップ・パスワード変更。
これらは Ledger アプリが対応するトランザクションの種類を確かめたうえで、1つずつ署名の流れ（`xxxWith(sign, …)` の形）に差し替えます。
Ledger アプリ自体が対応しない種類は、その画面で理由を案内します。

# Symbol

## 手数料の5段階と既定値(Symbol)

### 5段階の手数料速度
`src/lib/symbol/feeSpeed.ts` に定義。ノードの `/network/fees/transaction`(最小・中央値・最大)から計算します。

| 段階 | キー | 手数料倍率 |
|---|---|---|
| 最も遅い | `slowest` | ネットワーク最小 |
| 遅い | `slow` | 最小と標準の中間 |
| 標準 | `standard` | 直近ブロックの中央値 |
| 速い | `fast` | 標準の2倍 |
| 最も速い | `fastest` | 標準の3〜4倍(直近の最大値、4倍で頭打ち) |

- 以前の3段階(遅い/標準/速い)のうち、「遅い」はネットワーク最小のことでしたが、現在は「最も遅い」がそれにあたります。
- 標準より遅い段階(最も遅い・遅い)では「承認されず期限切れになる場合があります」と警告します。
- 選べる画面: 送金フォーム、アグリゲート、ハーベスティングのキーリンク(プルダウン形式。送金・キーリンクは各段階の手数料額も表示)。

### 手数料の既定値
- 設定 > 「手数料の既定値」(Symbolのみ)で選びます。端末に保存されます(初期値は標準)。
- 各画面の手数料選択の最初の選択になります(送金・アグリゲート・キーリンク)。
- 速さを選べない操作(モザイク作成・供給量変更・ネームスペース登録・エイリアス・メタデータ・アカウント制限・マルチシグ変換・投票鍵・委任リクエストなど)も、この速さで支払います。
- NEM(NIS1)の手数料は固定式のため対象外です。

## Symbolのノード管理

設定 > 「ノード」(Symbol選択時)で開きます。NEM選択時は従来の画面のままです。

### できること
- **一覧**: ネットワーク(メインネット/テストネット)ごとに登録したノードを表示。「自動選択」か登録ノードのどれかを選びます(選んだノードが `customNodes`)。
- **追加**: URLを入力して「追加」。接続テスト(正常稼働・同じネットワークか)に通ったものだけ登録できます。「公開ノードから追加」で、公開ノード一覧から稼働中のものをタップして追加することもできます。
- **削除**: ごみ箱ボタン。使用中のノードを削除すると自動選択に戻ります。
- **接続テスト**: 各ノードのボタンで1件、「すべて接続テスト」で全件。結果は応答時間(ms)か「接続できません」。
- **利用できないとき自動で切り替える**(既定はオン): 選んだノードが応答しないとき、登録済みの他ノード→自動選択のノードの順に切り替えます。切り替わると画面下に通知が出て、ダイアログの「現在」に「自動切替中」と表示されます。選んだノードは5分ごとに再確認し、復旧すれば自動で戻ります。オフにすると、選んだノードが失敗したときはエラーのままです。

## 他アカウント宛てのメタデータ（連署が必要な付与）— Symbol

「メタデータ」画面（`/metadata`）の一番上に「付ける相手」の切替（**自分** / **他のアカウント**）が加わりました。これまでは自分のアドレス・自分が作成したモザイク・自分が登録したネームスペースにしか付けられませんでしたが、「他のアカウント」を選ぶと、相手のアカウント（アドレス・相手が作成したモザイク・相手が登録したネームスペース）にメタデータを付けられます。モザイク画面・ネームスペース画面のダイアログ（その場で付ける画面）は従来どおり自分の対象のみです。

### 仕組み
- このウォレットがメタデータの**付与元（source）**、相手が**付与先（target）**です。Symbol の仕様で付与先の署名が必要なので、**ボンデッドアグリゲート**で送ります（ハッシュロック → 署名待ちとして送信 → 相手が連署して反映）。
- ハッシュロックの預け金（既定 10 XYM）と手数料はこのウォレットのXYMから払います。預け金はアグリゲートが承認されると戻ります。手数料には相手の署名分の余裕が含まれます。
- 相手が**マルチシグアカウント**のときは、その連署者の署名（minApproval 分）が必要です。このウォレットが連署者で minApproval が 1 なら、署名待ちにならず完全アグリゲートでそのまま送られます（マルチシグ送金と同じ考え方）。
- 保存されるのは「付与元 + 付与先 + キー」ごとです。**相手自身が同じキーに付けた値は上書きされません**（別のエントリーです）。画面に出る「あなたが設定済みのメタデータ」も、あなたが付けた分だけです。同じキーに付け直すと、あなたの値が上書きされます。

### 画面の動き
1. 「付ける相手」で「他のアカウント」を選び、相手を入力します。**アドレス**、**ネームスペース名**（`nem.group` / `@nem.group`。調べた実アドレスを使います）、**公開鍵**が使えます。アドレス帳（選択中のネットワークのSymbol）から選ぶこともできます。
2. 相手がネットワークに公開鍵を登録していない（一度も署名したトランザクションを送っておらず、受け取ってもいない）と、連署できないので指定できません。必要な連署の人数が入力欄の下に出ます。自分のアドレスは指定できません（「自分」を使います）。
3. 付ける対象（アドレス / モザイク / ネームスペース）を選びます。モザイク・ネームスペースは**相手が所有するもの**の一覧です。
4. キーと値を入れて「確認画面へ」。確認画面に、対象アカウント・手数料・ハッシュロック（預け金とその手数料）・「相手が署名するまで反映されない」が出ます。
5. パスワードで送信。完了画面に「署名待ちとして送信しました」と**連署依頼QR**（マルチシグ画面と同じもの）が出ます。

### 相手側（連署する人）
- 署名待ちの一覧と、署名QR画面（オフライン連署を含む）に「メタデータの付与」として、**付与元・付与先アカウント・対象（アドレス/モザイク/ネームスペース+ID）・キー・値**が出ます。
- 値は、新しいキーならそのまま表示します。既存キーの更新は、トランザクションの中身が「旧値とのXOR」なので、オンラインでは現在の値から変更後の値を計算して表示します。**オフラインで更新だと分かるとき（旧値が分からないとき）は、XORの生データを値のように見せず**、「変更の内容（旧値とのXOR）」と文字数の増減で出します。

### 変更したファイル
- `src/lib/symbol/tx.ts` — `MetadataChange.targetAddress`（付与先）、`signMetadata` の `bonded` / `cosignatureCount`（連署分の手数料）。自分宛ては従来どおり完全アグリゲートで、バイト列も変わりません。
- `src/lib/symbol/api.ts` — `MetadataTargetRef.sourceAddress`（付与元。他アカウントの対象では自分が付けた分だけを読む）、`fetchMetadataValue` を公開。
- `src/lib/symbol/metadataOther.ts`（新規）— 相手の入力解決、費用見積り、ハッシュロック + ボンデッド送信。
- `src/lib/symbol/metadata.ts` — メタデータ種別コード、変更後の値の計算（`applyValueChange`）。
- `src/lib/symbol/multisigApi.ts` / `payloadSummary.ts` — 署名待ち・署名QRでメタデータを読む（`PartialItem` に `metadata`）。
- `src/pages/metadata/MetadataPage.tsx`, `src/pages/multisig/parts.tsx`, `src/i18n/messages.json`（日・英）。
- `dev-tests/metadata-other-account.test.ts` — `npx tsx dev-tests/metadata-other-account.test.ts`（34項目。通信なし）。

### 制限
- 閲覧用プロファイルでは、これまでどおりメタデータは付けられません（署名が要らない操作のみ）。
- 期限切れのネームスペース、相手が作成していないモザイクは選べません。
- 実ネットワークでの送信は未確認です。テストネットで、①ハッシュロック → 署名待ち、②相手のウォレットの署名待ちに出ること、③連署後の反映、を確かめてください。署名待ちの一覧に出ないときは、連署依頼QR（またはハッシュ）から署名できます。

## 他の人が付けたメタデータの表示（閲覧のみ）

「メタデータ」画面（`/metadata`）の「設定済みのメタデータ」の下に、**「他の人が付けたメタデータ」**が加わりました。選んでいる対象（アドレス / モザイク / ネームスペース。「自分」でも「他のアカウント」でも）に、**あなた以外のアカウントが付けたエントリー**を一覧で表示します。モザイク画面・ネームスペース画面のダイアログ（組み込み表示）にも同じ一覧が出ます。

## アカウント制限（Account Restrictions）— Symbol

「アカウント」画面（サイドメニュー）の中の「アカウント制限」セクション（Symbol のみ）。選んだアカウントの現在の制限が一覧表示され、「制限を編集」で編集画面が開きます（サイドメニューの独立項目と `/restriction` は廃止）。編集は選んだアカウントを対象に、そのアカウントのパスワード・鍵で署名します。アカウントが「やり取りできるアドレス」「受け取れるモザイク」「送れるトランザクションの種類」を、ブロックチェーン上で制限します。

### 3つの制限

| タブ | 方向 | 使うトランザクション | フラグ（`restrictionFlags`） |
|---|---|---|---|
| アドレス | 受信 / 送信 | `account_address_restriction_transaction_v1`（0x4150） | `0x0001`（許可・受信）`0x4001`（許可・送信）`0x8001`（ブロック・受信）`0xC001`（ブロック・送信） |
| モザイク | 受信のみ | `account_mosaic_restriction_transaction_v1`（0x4250） | `0x0002`（許可）`0x8002`（ブロック） |
| オペレーション | 送信のみ | `account_operation_restriction_transaction_v1`（0x4350） | `0x4004`（許可）`0xC004`（ブロック） |

- **許可リスト** = リストにあるものだけ許可 / **ブロックリスト** = リストにあるものを拒否。
- 1つのトランザクションで編集できるのは1つのリスト（種類 + 方向）だけです。追加と削除は同じトランザクションに混ぜられます。
- アグリゲートではなく単独のトランザクションで、署名するのは制限をかけるアカウント自身です。

### 画面の動き
1. 現在の設定を `GET /restrictions/account/{address}` で取得して表示（設定がないアカウントは 404 なので「未設定」）。
2. タブ（アドレス / モザイク / オペレーション）と、アドレスのときは方向（受信 / 送信）を選ぶ。
3. 既存の値は削除ボタンで「削除予定」にでき、新しい値は追加欄から足す（アドレス帳・保有モザイクから選べる。オペレーションは一覧から選ぶ）。
4. 手数料を見積もって「確認画面へ」→ パスワード → 送信。送信後はノードの判定（失敗コード）を見て、分かりやすいメッセージを出す。

### 画面側で止めているもの（誤設定で戻せなくなるのを防ぐ）
- **値が1つでもあるリストは、モードを変えられません**（ノードが許可↔ブロックの変更を拒否するため）。変えたいときは、いったん全部削除。
- **オペレーションの許可リストには「アカウントのオペレーション制限」（0x4350）が必須**。入れないと、あとから制限を変更できなくなります（ブロックリストには逆に入れられません）。
- 自分自身のアドレス、選択中のネットワーク以外のアドレスは指定不可。
- 1リスト 512 件、1回の変更は追加・削除それぞれ 255 件まで。

### 閲覧用プロファイル
署名が要らないので、現在の設定は見られます（メニューにも出ます）。追加・削除・送信の操作は画面に出ません。

### マルチシグアカウントの制限を、連署者として変更する
このウォレットが連署者になっているマルチシグアカウントがあると、画面の上に「制限をかけるアカウント」の選択が出ます（連署者でなければ出ません）。

- 選ぶと、そのマルチシグアカウントの現在の制限を表示し、追加・削除ができます。タブ・モード・入力チェックは自分のアカウントと同じです。
- 制限の変更は、マルチシグアカウント名義のアグリゲートに入れて、このウォレットが署名します。承認に必要な署名（minApproval）が1なら「完全アグリゲート」でそのまま送信、2以上なら「ボンデッド」（ハッシュロック → 署名待ちとして送信）です。マルチシグ送金と同じ流れです。
- 手数料（と署名待ちのときのロック金額）は、マルチシグアカウントではなく**このウォレットのXYM**から払います。画面の費用欄とパスワード前の確認で金額が見えます。
- 署名待ちで送ったときは、完了画面に連署依頼QRが出ます。他の連署者は、マルチシグ画面の「署名待ち」やオフライン連署で、制限の中身（対象・許可/ブロック・追加/削除する値）を確認してから署名できます（以前は「その他の操作」としか出ませんでした）。
- 「自分のアドレス」の禁止は、制限をかけるマルチシグアカウント自身に対して働きます。連署者のウォレットのアドレスはリストに入れられます。
- マルチシグアカウントの公開鍵がネットワークに未登録のときは、変更できません（マルチシグ送金と同じ）。
- 追加の注意表示: マルチシグアカウントのオペレーション許可リストに「マルチシグ設定の変更」（0x4155）が入っていないと、連署者や承認数をあとから変えられなくなるため、警告を出します（送信は止めません）。

## 委任リクエストの再送 — Symbol

「ハーベスト」画面の「デリゲートハーベスティング」タブで、ハーベストが設定済み（リモート・VRF・ノードの3つがリンク済み）のとき、
下に「委任リクエストの再送」が出ます（Symbol のみ）。

### いつ使うか
リンクは済んでいるのに、ノードがリクエスト（リモート／VRFの秘密鍵を、ノードの公開鍵で暗号化したメッセージ）を受け取れていないとき
（ノードの再起動やデータの消失など）。**リンクは変えず**、リクエストだけをもう一度送ります。

### 使うトランザクション
- `transfer_transaction_v1`（モザイクなし）をリンク中のノードのアドレスへ。メッセージは `FormPersistentDelegationRequest`
  （先頭 0xFE のマーカー 8 + 一時公開鍵 32 + AES-GCM タグ 16 + IV 12 + 暗号文 64 = 132 バイト）。開始時と同じ `signHarvestDelegation`。
- 送り先は**チェーン上でリンクされているノード**に固定（画面では選べません。ノードを変えるときは停止→再開始）。

### 鍵の保存（開始時）
「開始（自動生成）」で作るリモート／VRFの秘密鍵は、**パスワードで暗号化してこの端末に保存**します（`Wallet.encryptedHarvestKeys`、秘密鍵と同じ暗号化方式）。
- ブロック作成専用の鍵で、**送金には使えません**。保存先はこのアカウントだけ。
- 保存は、リンクを送る**前**に行います。リンクが成功したのに依頼の送信だけ失敗しても、保存した鍵で再送できます。リンク自体が拒否されたときは、保存を取り消します。
- パスワードを変えると、保存した鍵も新しいパスワードで暗号化し直します。
- 停止したとき、およびリモート／VRFのキーを別の鍵に付け替えたときは、保存した鍵を消します（もう合わないため）。
- 以前のバージョンで開始した分は保存がありません（下の「保存がない場合」）。

### 画面の動き
「ハーベスト」の「デリゲートハーベスティング」タブで、3つのキー（リモート・VRF・ノード）がリンク済みのとき、下に「委任リクエストの再送」が出ます。
1. **保存した鍵がある場合**: 「保存した鍵で再送する」→ 手数料と送り先の確認 → パスワード → 送信。鍵の入力は要りません。
   「保存した鍵を表示」は、パスワードを入れると2つの秘密鍵を見せます（控えるため）。閉じると画面の状態から消します。
2. **保存がない場合・別の鍵を使う場合**: リモートの秘密鍵とVRFの秘密鍵（64文字の16進、伏せ字）を入力して再送。
3. どちらも、鍵から公開鍵を作り、**チェーン上のリモート／VRFの公開鍵と一致**したときだけ送ります（別の鍵を送ってもノードは何もできず、鍵をさらすだけのため）。
   送信の直前にチェーンを読み直して、もう一度突き合わせます。合わなければ送りません。
4. 送り先は**チェーン上でリンクされているノード**に固定です（ノードを変えるときは停止→再開始）。リンクは一切変えません。

### 保存がない場合
鍵を控えてあればそれを入力して再送できます。控えがなければ、いったん停止してから開始し直してください（新しい鍵が作られ、今度は保存されます）。

### 実装メモ
- 判定（通信なし）: `src/lib/symbol/harvestKeys.ts` の `planDelegationResend`。鍵→公開鍵は `tx.ts` の `harvestPublicKeyOf`。
- 通信: `src/lib/symbol/api.ts` の `resendHarvestDelegation`（鍵が合わないときは `SymbolSendError('delegation_keys_mismatch')`、リンクが揃っていないときは `'not_linked'`）。
- 鍵の保存: `src/lib/storage.ts` の `Wallet.setHarvestKeys` / `decryptHarvestKeys`（パスワード変更で `encryptSecret` が一緒に暗号化し直す）、`WalletsHelper.saveHarvestKeys` / `loadHarvestKeys` / `clearHarvestKeys`。開始時は `api.ts` の `startHarvesting` の `keyStore`（リンクを送る前に保存、リンクが拒否されたら破棄）。
- 画面: `src/pages/harvest/ResendDelegationPanel.tsx`、送信の流れは `HarvestSettings.tsx` の `resend` アクション。
- 文言: `messages.json` の `harvest.resend_*` / `harvest.error_resend_keys_*`（ja / en）。
- テスト: `dev-tests/harvest-keys-storage.test.ts`（保存・パスワード変更・壊れたデータ、13項目）と `dev-tests/harvest-delegation-resend.test.ts`（`npx tsx dev-tests/harvest-delegation-resend.test.ts`、26項目。ノード側で復号して2つの鍵が取り出せることも確認）。

## 投票鍵（Voting Key）のリンク／解除 — Symbol

「ハーベスト」画面の「キーリンク」タブの下側に、投票鍵（ファイナライズ用の BLS 公開鍵）のリンク・解除が加わりました（Symbol のみ。NEM の「投票」機能とは別物です）。

### 使うトランザクション
- `voting_key_link_transaction_v1`（0x4143）: 投票用公開鍵（48バイト＝16進96文字）・開始エポック・終了エポック・リンク／解除。
- 他のキーリンクと同じく `aggregate_complete_transaction_v3` に入れて送ります（署名するのはアカウント自身）。
- 手数料の見積もりサイズ: `128 + 40 + 112 × リンク数`（埋め込み1件 = 48 + 57 = 105 → 112 に切り上げ）。

### 画面の動き
1. 「現在のリンク」: アカウント情報 `supplementalPublicKeys.voting.publicKeys` の一覧（開始エポック順）。各行に公開鍵・エポック範囲・状態（開始前／有効／期限切れ）と「解除」ボタン。
2. リンク: 公開鍵（96文字）・開始エポック・終了エポックを入力して「リンク」。開始・終了は、`/chain/info` の確定エポック＋2 から、ネットワークが許す最長の期間を初期値として入れます（変更可）。
3. 手数料を表示 → 確認ダイアログ（リンク／解除の内容とエポックを列挙）→ パスワード → 送信。

### 画面側で止めているもの
- 公開鍵は **96文字**（64文字のアカウント公開鍵は不可）。
- 期間（終了 − 開始 + 1）は、ネットワークの最小〜最大（`/network/properties` の `minVotingKeyLifetime` / `maxVotingKeyLifetime`、読めないときは 28〜720）の範囲内。
- すでにリンクされている期間と **重なる範囲はリンク不可**。同時にリンクできる数は `maxVotingKeysPerAccount`（既定 3）まで。
- **解除は、チェーン上のリンクと「公開鍵・開始・終了」が完全に一致する必要がある**ため、入力させず、一覧の値をそのまま使います。送信の直前にチェーンを読み直し、変わっていたら送らずに状態を更新します。

### 扱わないもの
投票鍵の**秘密鍵**は扱いません（ノード側の投票鍵ファイルで設定します）。この画面は公開鍵のリンク／解除だけです。

### 実装メモ
- 判定ロジック（通信なし）: `src/lib/symbol/votingKeys.ts` — テスト `dev-tests/voting-keys.test.ts`（`npx tsx dev-tests/voting-keys.test.ts`、43項目）。
- 署名: `src/lib/symbol/tx.ts` の `signVotingKeyLinks` / `votingLinkSize`。
- 通信: `src/lib/symbol/api.ts` の `fetchHarvestStatus`（`votingKeys` を追加）・`fetchVotingContext`・`quoteVotingFee`・`changeVotingKeys`。
- 画面: `src/pages/harvest/VotingKeyPanel.tsx`（`KeyLinkPanel` に組み込み）、送信の流れは `HarvestSettings.tsx` の `voting` アクション。
- 文言: `messages.json` の `harvest.voting_*`（ja / en）。

- 当時と同じ確かめ方で、**NIS1 の鍵を入れていないか**を NEM ノードに聞く（公開鍵として見た NEM アドレスと、秘密鍵として見た NEM アドレスの、どちらにも残高も公開鍵の記録も無いこと）。聞けなかったときは受け付ける。

# NEM

## NEM の即時更新・通知・効果音

Symbol と同じく、NEM でも次のタイミングで通知と効果音が出ます（設定の「新着の通知」「通知音」で切替。Symbolと共通）。

- 取引を出した（ノードに受け付けられた＝未承認）→ `ding`
- 取引が承認された（ブロックに入った）→ `ding2`
- 自分宛ての着金も同様

### 仕組み
NEM も Symbol と同じく WebSocket で受け取ります。NIS1 にも WebSocket API があり（STOMP。公式 NEM Wallet は SockJS 経由）、`lib/nem/liveSocket.ts` が `wss://<ノード>:7779/w/messages/websocket` につなぎます。つながらないときは、これまでどおりノードを確認する方式に自動で戻ります。

- **つなぎ方**: `CONNECT` → `/w/api/account/subscribe` に自分のアドレスを送る → `/unconfirmed/<アドレス>`（ノードが取引を受け取った＝未承認 → `ding`）と `/transactions/<アドレス>`（ブロックに入った＝承認 → `ding2`）を購読。公式の NEM Wallet（nem-sdk / nem-library）と同じ手順です。STOMP は `lib/nem/stomp.ts` の小さな実装で、外部ライブラリは使いません。
- **どのノードにつなぐか**: 普段使っている REST ノードの同じホスト（`https://host:7891` なら `wss://host:7779`）を先に、続けて同じネットワークの別ノードを最大3つ。手入力したカスタムノードのときは、そのホストだけです。wss（7779番）を出しているノードだけが使えます。
- **つながらないとき・切れたとき**: つなぎ直しを繰り返します（3秒→8秒→20秒→60秒→120秒と間隔を延ばし、つながっていたのが切れたときは1.5秒後）。ハートビートが途切れた接続も切ってつなぎ直します。
- **確認方式（安全網）**: これまでの確認（未承認一覧 `/account/unconfirmedTransactions` と最新の承認済み `/account/transfers/all`）は残してあります。WebSocket がないあいだは6秒ごと、あるあいだは30秒ごと（WebSocket が取りこぼしたものを拾うため）。つながった直後にも1回確認します。
- **二重に鳴らない**: WebSocket と確認方式の知らせは、同じ取引ごとに1回だけ通すようにまとめています（`lib/nem/liveReporter.ts`）。通知どうしは最低1.2秒あけるので、`ding` と `ding2` が重なりません。
- **同じ取引かどうかの見分け方**: 承認前の一覧・承認済みの一覧・WebSocket は、同じ取引でも `meta` のハッシュを入れる場所が違い（`meta.data` / `meta.hash.data`。マルチシグは包んでいる取引のハッシュ）、ハッシュだけでは別の取引に見えます。そこで取引の**署名**とハッシュのどれかが一致すれば同じ取引として扱います（`liveIds`）。これで、自分が出した取引（または WebSocket で承認前を知らせた取引）は、承認されたときに `ding` が鳴り直さず、`ding2` だけが鳴ります。
- **「承認前」を一度も見ていない取引だけ**: 確認方式だけだと、確認と確認のあいだにブロックに入った取引は承認済みの状態で初めて見えます。その取引には「承認前」の通知（`ding`）を先に出し、続けて「承認」（`ding2`）を出します。Symbol と同じく、新しい取引では必ず2回鳴ります（起動直後の1回目に記録した過去の取引を除く）。
- 画面を隠している間（バックグラウンド。たとえば faucet のページを開いている間）も、WebSocket と確認は続きます（ブラウザが間隔を延ばすことはあります）。以前は確認を止めていたため、その間に「承認前」が過ぎて `ding2` しか鳴りませんでした。
- 送信（`announceNemPayload`）の直後は `lib/nem/liveSignal.ts` 経由ですぐ確認します。
- 起動直後の1回目は「今あるもの」を記録するだけで、過去の取引では鳴りません。
- 通知の表示・画面の更新・音は `components/LiveUpdates.tsx` が Symbol/NEM 共通で処理します。
- 接続の様子は診断ログ（`nem-live`）に出ます（「WebSocket connected: wss://…」「WebSocket not available: …（理由）」など）。WebSocket につながらないノードでは「not available」が数回出たあと、間隔をあけて静かに再試行します。
- テスト: `npx tsx dev-tests/nem-live-socket.test.ts`（STOMP の組み立て・解析、通知のまとめ方、手作りの STOMP サーバーを相手にした接続・再接続・切り替え・ハートビート切れ）

## NEM: モザイクの送金

NEM の送金で、XEM 以外のモザイクも送れるようにした（NanoWallet と同じく、複数のモザイクを1回の送金に添付できる）。

### 画面
- 「送る」のモザイク選択に、持っているNEMモザイクが並ぶ。可分性（小数桁）は NIS1 のモザイク定義から読むので、金額は小数で入力する。
- 「モザイクを追加」で、同じ送金に別のモザイクを足せる（最大10種類。XEM も1行として足せる）。
- レビー（送るたびに送る側が追加で払う手数料）付きのモザイクを選ぶと、警告を出す。
- 手数料は XEM 建てで、モザイクの種類・数量・メッセージから計算して表示する。

### 仕組み
- XEM だけの送金は従来どおり TransferTransactionV1。モザイクを含むと TransferTransactionV2 になり、`amount` は倍率 1,000,000（= ×1）、各モザイクの数量は原子単位でそのまま入れる。
- 手数料は SDK の `calculateTransactionFee`（NIS1 と同じ規則）で計算する。供給量が 10,000 以下で可分性 0 の「小規模モザイク」は 0.05 XEM、それ以外は XEM 換算額から。メッセージは 32 バイトごとに 0.05 XEM。
- 定義は `/namespace/mosaic/definition/page` から読み、セッション中は覚えておく（`lib/nem/api.ts` の `fetchNemMosaicInfos`）。
- 定義が読めなかったモザイクは、可分性を推測しないよう送信候補に出さない（残高の一覧には従来どおり出る）。
- 送金の直前にもう一度定義を読み、その可分性で金額を原子単位に直してから署名する。

### 送れないもの・注意
- 譲渡不可（transferable = false）のモザイクは、作成者のアカウントからだけ送れる。それ以外は候補に出さない。
- 供給量が変更可能なモザイクで、供給量を変えたことがあるもの: 手数料は定義の初期供給量で計算する。実際の供給量と違うと手数料不足で拒否されることがある。
- レビーは手数料に含めない（NIS1 が送る側の残高から別に引く）。残高が足りないとノードが拒否する。
- マルチシグ名義の送金（NemMultisigSend）とインボイス QR は、これまでどおり XEM のみ。
- 実ネットワークでの送信は未確認（テストはオフラインでの組み立て・署名・復元まで）。まずテストネットで、小規模モザイクと可分性ありのモザイクを少額で試すこと。Ledger での署名も同様。

### テスト
`npx tsx dev-tests/nem-mosaic-transfer.test.ts`（手数料の規則、V2 の署名と復元、XEM 単独が V1 のままであること）。

## NEM: 暗号化メッセージの送信と復号

NanoWallet と同じく、NEM の送金メッセージを宛先の公開鍵で暗号化して送れる。受け取った（自分が送った）暗号化メッセージは、取引の詳細画面で復号して読める。

### 送る
- 「送る」画面の「メッセージを暗号化する」スイッチが NEM でも使える。宛先の公開鍵がネットワーク上にあるとき（一度でも送信したことのあるアカウント）だけオンにできる。
- 暗号化するとメッセージは 975 バイト（UTF-8）まで。暗号文は塩32 + IV16 + 16バイト単位に詰めた本文で、1024 バイトの上限に収まる長さ。
- 手数料はチェーンに載る暗号文の長さで計算する（同じ文でも平文より少し高い）。
- 暗号化は送る側の秘密鍵が要るので、Ledger のアカウントでは送れない（確認画面で止める。黙って平文にはしない）。
- 暗号化メッセージはモザイク添付・複数モザイクの送金とも併用できる。マルチシグ名義の送金は従来どおり平文のみ。

### 読む
- 取引の詳細画面で、暗号化メッセージに「復号して表示」ボタンが出る。パスワードを入れると本文が出る（復号した本文は画面の中だけで、保存しない）。
- 受け取ったメッセージは送り手の公開鍵（取引に入っている）で、送ったメッセージは宛先の公開鍵（ノードから取得）で読む。
- 閲覧用プロファイルと Ledger のアカウントには秘密鍵が無いのでボタンを出さない。
- 履歴の一覧では、これまでどおり「暗号化されています」と出る。

### 形式
NanoWallet と NEM のモバイルウォレットが読み書きする、旧来の AES-CBC 形式（塩 + IV + 暗号文）で書く。SDK が「推奨」とする AES-GCM 形式はそれらのウォレットが読めないので、書き込みには使わない。読むときは両方の形式を試す。

### 注意
- 暗号文の長さと手数料は NIS1 の規則に合わせてあるが、実ネットワークでの送信と、NanoWallet との相互の読み書きは未確認。テストネットで、KASANE → NanoWallet、NanoWallet → KASANE の両方向を少額で試すこと。
- 暗号化されるのはメッセージの本文だけ。宛先・金額・送り手は誰にでも見える。

### テスト
`npx tsx dev-tests/nem-encrypted-message.test.ts`（往復、第三者が読めないこと、CBC の長さ、手数料、署名した取引の種別2）。

## NEM 署名付きメッセージ（作成と検証）

NanoWallet の「署名付きメッセージ」にあたる機能。**サービス > 署名付きメッセージ**（NEM。Symbol にも同じ機能がある: 次の「Symbol 署名付きメッセージ」）。

### 画面（NanoWalletの2画面にならった2カラム）
- 広い画面では左に入力、右に結果。スマホでは縦に並ぶ。タイトルは「署名付きメッセージの作成」「署名付きメッセージの検証」。
- 作成: 左＝署名するアカウント・メッセージ・「署名する」。右＝署名付きメッセージ（署名前は空欄）。署名すると右に「KASANE / NanoWallet」の切り替えが出て、選んだ形式のテキストをそのまま コピー・.json保存・QR にできる。その下に、アドレス・公開鍵・メッセージ・署名。
- 検証: 左＝署名付きメッセージのテキストを貼る欄と「検証する」（貼って押すだけ）。「メッセージ・公開鍵・署名を別々に入力する」を開くと、3つを別々に入れたり、アドレス（任意）を入れたりできる。右＝結果（正しい／正しくない／アドレス違い）と、確かめたアドレス・公開鍵・メッセージ・署名。

### 署名を作成
- 署名するアカウント（NEM）と、メッセージを入れて「署名する」→ パスワード。
- 署名の対象は **メッセージの UTF-8 バイト列そのもの**（空白・改行も1文字ずつ）。署名は Ed25519 / Keccak-512（NEM の署名方式）の 128 桁 16 進。
- 出した署名は、公開鍵で検証してから表示する（合わない署名は渡さない）。
- 結果は、メッセージ・署名・公開鍵・アドレス。相手に渡す用に、3つを1つにした JSON（QR・コピー・.json 保存）も出る。
  ```json
  {"kasane":1,"kind":"nem_signed_message","data":{"message":"…","publicKey":"<64 hex>","signature":"<128 hex>"}}
  ```
- NanoWallet 用の形式も出る（右の「NanoWallet」に切り替え。QR・コピー・.json 保存）。NanoWallet の「署名付きメッセージを検証」にそのまま貼り付けられる。
  ```json
  {"message":"<署名したバイト列の16進>","signer":"<公開鍵 64 hex>","signature":"<署名 128 hex>"}
  ```
- ネットワークには何も送らない。トランザクションではなく、手数料もない。Ledger・閲覧用プロファイルは署名できない。
- 「意味のわからない文字列には署名しない」という注意を画面に出す。

### 署名を検証
- 上の JSON（または `{"message","publicKey","signature"}` だけの JSON）を貼り付けて「検証する」。別々に入れるときは、メッセージ・公開鍵（64桁）・署名（128桁）。
- 「アドレス（任意）」を入れると、公開鍵がそのアドレスのものかも確かめる（使っているネットワークの N… / T…）。
- NanoWallet の署名付きメッセージ（上の形式、`message` が16進）も貼り付けて読める。16進を文章に戻して検証する。
- 検証は、正しい UTF-8 と NanoWallet 式の符号化の両方を試す（下の「NanoWallet との互換」）。
- 結果は「署名は正しいです（署名したアドレス）」／「署名が正しくありません」／「署名は正しいが、アドレスが違う」。入力を変えると結果は消える。

### NanoWallet との互換
- 署名の中身は同じ（Ed25519 / Keccak-512 で、メッセージのバイト列に署名）。同じ秘密鍵・同じ文章なら、日本語・英数字・記号では **NanoWallet と同一の署名**になる（nem-sdk の出力と照合済み）。
- 違いは絵文字など（サロゲートペアの文字）だけ。NanoWallet は UTF-16 の 1 単位ずつ 3 バイトに符号化する（正しい UTF-8 では 4 バイト）ので、同じ文章でも署名が変わる。
  - NanoWallet の署名 → KASANE で検証: JSON を貼る、または文章を入れて検証すると、NanoWallet 式の符号化でも照合するので正しいと出る（その旨の注記が出る）。
  - KASANE の署名 → NanoWallet で検証: 「NanoWallet用」の JSON を貼る。message は署名したバイト列そのものの16進なので、そのまま検証できる。文章を NanoWallet で打ち直した場合は、絵文字があると合わない。
- 共有 JSON の読み取り: `publicKey` がなく `signer` がある JSON で、`message` が16進なら NanoWallet 形式として扱う（`publicKey` がある JSON の `message` は、16進に見えても文章のまま）。

### ファイル
`src/lib/nem/signedMessage.ts`（形式・共有 JSON・NanoWallet 形式と符号化。SDK なし）／`src/lib/nem/crypto.ts`（`signNemData`・`verifyNemText`）／`src/pages/nem/NemSignedMessage.tsx`／`router.tsx`・`ServiceHub.tsx`・`NavigationDrawer.tsx`・i18n 5言語

### テスト
- `npx tsx dev-tests/nem-signed-message.test.ts` … SDK なし（形式・共有 JSON・NanoWallet 形式の読み書き・符号化）
- `npx tsx dev-tests/nem-signed-message-sign.test.ts` … SDK（署名→検証、1文字違いで失敗、決定的、nem-sdk が出した NanoWallet の署名との照合）

### 画面
- NEM と同じ（広い画面は左に入力・右に結果、スマホは縦）。タブは「署名を作成」「署名を検証」。

### 署名を作成
- 署名するアカウント（Symbol）と、メッセージを入れて「署名する」→ パスワード。署名の対象は **メッセージの UTF-8 バイト列そのもの**（空白・改行も1文字ずつ）。署名は Ed25519 / **SHA-512**（Symbol の署名方式）の 128 桁 16 進。
- 出した署名は、公開鍵で検証してから表示する。結果は、メッセージ・署名・公開鍵・アドレスと、3つを1つにした JSON（QR・コピー・.json 保存）。
  ```json
  {"kasane":1,"kind":"symbol_signed_message","data":{"message":"…","publicKey":"<64 hex>","signature":"<128 hex>"}}
  ```
- ネットワークには何も送らない。トランザクションではなく、手数料もない。**Ledger・閲覧用プロファイルは署名できない**（Symbol の Ledger アプリは任意のバイト列に署名しない）。
- 「意味のわからない文字列には署名しない」という注意を画面に出す。

### 署名を検証
- 上の JSON（または `{"message","publicKey","signature"}` だけの JSON）を貼り付けて「検証する」。別々に入れるときは、メッセージ・公開鍵（64桁）・署名（128桁）。
- 「アドレス（任意）」を入れると、公開鍵がそのアドレスのものかも確かめる（使っているネットワークの N… / T…）。
- 結果は「署名は正しいです（署名したアドレス）」／「署名が正しくありません」／「署名は正しいが、アドレスが違う」。入力を変えると結果は消える。

### NEM との違い
- **署名方式が違う**（NEM は Ed25519 / Keccak-512、Symbol は Ed25519 / SHA-512）。同じ秘密鍵でも公開鍵・署名が違うので、NEM の署名付きメッセージを Symbol で検証することはできない（逆も同じ）。NEM の署名付きメッセージ（KASANE の封筒、NanoWallet 形式）を貼ったときは、そのことを教える。
- NanoWallet 形式の出力・読み取りと、絵文字の符号化の違いは Symbol 側には無い。署名の対象は正しい UTF-8 のみ。

### ファイル
`src/lib/symbol/signedMessage.ts`（形式・共有 JSON・NEM との見分け。SDK なし）／`src/lib/symbol/crypto.ts`（`signData`・`verifySignature`）／`src/pages/signmsg/SymbolSignedMessage.tsx`／`router.tsx`（`/signed-message` は `ByChain`）・`ServiceHub.tsx`・`signingAccounts.ts`（`noLedger`）・i18n 5言語

- `npx tsx dev-tests/symbol-signed-message-sign.test.ts` … SDK（RFC 8032 の既知の答え、日本語・改行を含む文章、1文字違いで失敗、決定的、共有 JSON を通しても検証できる）

## NEM オフライン取引（作成・QR化・後から送信）

NanoWallet のオフライン取引にあたる機能です。KASANE ではこの 2 画面でできます。

### 作る（ネットに接続しない端末）
`オフライントランザクション` → 「転送トランザクション」 → ブロックチェーンで **NEM** を選ぶ。

- 送信元（NEMのアカウント）／送り先／XEM（と、オンラインで残高を表示したときに覚えたモザイク）／メッセージ／有効期限（1〜24時間）
- **ノードへは一切問い合わせない。** 手数料は NIS1 の規則でこの端末が計算する（NEM に倍率はない）。期限はこの端末の時計から決める。
- メッセージは平文のみ（暗号化には相手の公開鍵をチェーンから取る必要があるため）。
- 結果は QR / JSON テキスト / .json ファイル。中身は `POST /transaction/announce` の本文 `{"data","signature"}` を KASANE の封筒に入れたもの。
  ```json
  {"kasane":1,"kind":"nem_signed","network_id":104,"data":{"data":"<hex>","signature":"<hex>"}}
  ```
- Ledger のアカウント・閲覧用プロファイルは署名できないので、一覧に出ない。

### 送る（ネットに接続した端末）
`署名・連署QR`（設定の「QRコードのインポート」も同じ）で、QR読み取り・画像・JSONファイル・貼り付けのいずれかで読み込む。

- 署名済みバイト列そのものから、送り先・金額・モザイク・メッセージ・手数料・期限を読んで表示する（QR の自己申告は使わない）。
- 署名を署名者の公開鍵で検証する。ネットワークが違う、署名が合わない、転送以外のトランザクションは送れない。
- 期限切れは送れない。ボタンを押すまで何も送信しない。
- NanoWallet が出す `{"data","signature"}` の本文そのままも読める。
- NEM のトランザクションハッシュは、送信時にノードが返す（オフラインでは表示しない）。

### 制限
- 作れるのは転送（XEM／モザイク）だけ。マルチシグ等は作れず、読み込み側も転送以外は送らない。
- NEM のモザイクは、オンラインで一度そのアカウントの残高を表示した後に選べる（供給量と可分性が手数料計算に要る）。

`OfflineSignPage.tsx`・`SignQrPage.tsx`・`signingAccounts.ts`・`lib/nem/tx.ts`（`timeoutSeconds`）・`lib/nem/api.ts`（残高表示時にモザイクを記憶）・`lib/mosaicCache.ts`・i18n 5言語。

- `npx tsx dev-tests/nem-offline-sign.test.ts` … SDK で署名 → 読み取り・署名検証

外部エクスプローラ型の閲覧画面（NanoWallet のホーム／アカウント／取引／ネームスペース・モザイク／アポスティーユの5画面）は作っていません（このウォレットには不要という判断）。
ファイルのハッシュを、0 XEM の送金のメッセージとして NEM のブロックチェーンに残し、あとからファイルが変わっていないかを確かめます。**ファイルそのものは送信しません**（計算は端末の中）。

### 3つのタブ
- **作成**：ファイル（最大25件・1件100MBまで）またはテキストを選び、種類（署名つき／公開）・ハッシュ方式（SHA256 / SHA3-256 / SHA3-512）・タグを決めて送信（パスワードを聞く）。終わると ZIP を保存（公証したファイル［名前に取引ハッシュ入り］・証明書PNG・履歴 .nty）。
- **監査**：保存したファイルを選ぶと、名前の取引ハッシュからノードの記録を引き、ファイルと照合（一致／不一致／記録なし／名前の形式違い／公証の記録ではない）。ノードに送るのは取引ハッシュだけ。
- **履歴**：この端末に残した記録の一覧（ネットワークごと）。.nty の書き出し・読み込み（NanoWallet の .nty も可）・消去。署名つきは「更新」（同じ専用アカウントに新しいハッシュを送る）。

### 仕組み（NanoWallet と同じ）
- メッセージ = `FE 4E 54 59`＋ハッシュ種別（公開 03/08/09、署名つき 83/88/89、旧 MD5=01/81・SHA1=02/82 は監査のみ）＋ハッシュ（公開）／ハッシュへの署名64バイト（署名つき）。
- NEM の「SHA3」は Keccak（標準の NIST SHA3 ではない）。
- 公開：公証用シンク（メインネット `NCZSJH…`／テスト `TC7MCY…`）に送る。署名つき：「自分の鍵でファイル名のSHA-256に署名 → 下位32バイトを秘密鍵」とした専用アカウントに送る（同じ人・同じ名前なら同じアカウント）。
- 手数料：公開(SHA256) 0.15 XEM、署名つき 0.20 XEM（0.05＋メッセージ32バイトごとに0.05）。
- 証明書は canvas で描くので日本語のファイル名もそのまま出る。QR は取引のエクスプローラーへのリンク。

### NanoWallet との違い
- 専用アカウントの**秘密鍵は保存しない**（自分の鍵とファイル名からいつでも計算でき、更新にも要らない）。.nty の `dedicatedPrivateKey` は空。
- 新規作成のハッシュ方式は SHA256 / SHA3-256 / SHA3-512 のみ（MD5・SHA1 は弱いので、古い公証の監査だけ対応）。
- マルチシグでの公証、「アポスティーユのメッセージ（所有権の移転）」は未実装。Ledger のプロファイルでは使えません（署名の対応が未確認のため）。

## NEM 投票機能（Voting）

公式 NEM Wallet（NanoWallet 2.7.1 同梱の `nem-voting`）と**互換**の投票機能です。
ここで作った投票は公式ウォレットの一覧にも表示され、公式ウォレットで作られた投票もここで投票・集計できます。
NEM チェーンのときだけ、左メニューに「投票」が出ます。

### 画面
| パス | 内容 |
|---|---|
| `/voting` | 公開インデックスの投票一覧（すべて/開催中/終了、もっと読み込む）。アドレスから開く。 |
| `/voting/poll/:address` | 説明・選択肢・結果（％と票数）・投票。パスワード確認 → 送信。 |
| `/voting/create` | 投票の作成（タイトル、説明、選択肢2〜10、終了日時、集計方法、複数選択、ホワイトリスト）。 |

### しくみ（nem-voting と同じ）
- 投票は NIS1 上の 0 XEM 送金メッセージで表現されます。
  - 投票のアドレス宛: `formData:` / `description:` / `options:` / `whitelist:`
  - 公開インデックス宛: `poll:{title,type,doe,address}`（最後に送るので、完成してから一覧に出ます）
  - 各選択肢に専用アドレス（投票アドレス + 選択肢の文字列から導出）。**その選択肢アドレスへ 0 XEM（メッセージなし）を送る = 投票**。
- 集計規則
  - 承認済みの 0 XEM・モザイクなしの送金だけが票（取引所などからの入金は票にならない）。
  - 終了後は、終了時刻までのブロックの票だけを数える。
  - 単一選択: 複数の選択肢に投票したアカウントの票は無効。複数選択: 重要度を選択数で割って按分。
  - 重要度で重み付け: 終了時点のインポータンス（取得できないノードでは現在値で代用し、画面に明記）。
  - ホワイトリスト: 作成者が追加したアドレスの票だけを数える。
- 選択肢アドレスが導出値と一致しない投票（改ざん・旧形式）は、結果は表示しますが**投票はできません**。
- 同じアカウント・同じタイトルの投票は作れません（アドレスが同じになるため）。

### 手数料

## ウォレットファイル（.wlt）の書き出しと読み込み（NEM）

NEM公式ウォレット（NanoWallet / nem-sdk）の**ウォレットファイル（.wlt）**を、KASANEの NEM アカウントで書き出し・読み込みできます。
ファイルはすべて端末の中で作られ・読まれます（アップロードも保存もしません）。KASANE独自の キーストア とは別の機能で、どちらも使えます。

### 使い方
- **書き出し**: NEM を選んだ状態で、メニューの「アカウント」でアカウントを選び、秘密鍵を表示（パスワード確認）すると、その下に「ウォレットファイル（.wlt）を書き出す」が出ます。
  ウォレット名（既定はアカウント名）と、ファイル用のパスワード（8文字以上・確認入力あり）を決めます。KASANEウォレットのパスワードとは別です。
  ファイル名は `<ウォレット名>.wlt`（公式ウォレットと同じ）。
- **読み込み**: NEM を選んだ状態で、メニューの「アカウント」→ 追加 →「秘密鍵でインポート」の中の「ウォレットファイル（.wlt）から読み込む」。
  ファイルを選ぶ → ファイルのパスワードを入力 → KASANEのパスワードを確認、の順で、いまのプロファイルにアカウントとして追加されます（秘密鍵を貼り付けた場合と同じ扱い）。

### ファイルの形式（公式ウォレットに合わせたもの）
.wlt は、次の JSON を UTF-8 にして **Base64** にしたテキストです。

```json
{
  "name": "ウォレット名",
  "accounts": {
    "0": { "brain": false, "algo": "pass:enc", "encrypted": "<hex 96桁>", "iv": "<hex 32桁>",
           "address": "N...(ハイフンなし)", "label": "Primary", "network": 104 }
  }
}
```
- `network`: `104`＝メインネット、`-104`＝テストネット。
- 秘密鍵の暗号化は nem-sdk と同じ: 鍵＝パスワード（UTF-8）に **Keccak-256 を20回**かけたもの（1回ごとに前の結果を入力にする）、
  暗号＝**AES-256-CBC（PKCS#7）**、IV＝ランダム16バイト、平文＝秘密鍵32バイト。
- 書き出すファイルは `pass:enc`（公式ウォレットで「秘密鍵をインポート」したウォレットと同じ種類）です。

### 読み込める .wlt
| algo | 内容 | 読み込み |
|---|---|---|
| `pass:enc` | 秘密鍵をインポートして作ったウォレット | ○ |
| `pass:bip32` | 公式ウォレットで新規作成（乱数）したウォレット | ○ |
| `pass:6k` | ブレインウォレット（パスフレーズを6000回ハッシュ） | ○（パスフレーズを入力） |
| `trezor` / `ledger` | ハードウェアウォレット（ファイルに鍵がない） | ×（「読み込めません」と表示） |

- ネットワークが mijin（96）のファイルは読み込めません。
- ファイルのネットワークと、いま選んでいるネットワーク（メインネット／テストネット）が違うときは、取り込まずに案内を出します。
- パスワードが違うときは、復号した鍵から作ったアドレスがファイルの `address` と一致するかで判定します（公式ウォレットの `checkAddress` と同じ考え方）。
- 改行や BOM が入っていても、Base64 でなく生の JSON でも読めます。
- 公式ウォレットが後から付ける `child`（リモートアカウント）は読み込み時に使わず、書き出すファイルにも入れません。

### 注意
- 書き出した .wlt には暗号化された秘密鍵が入っています。パスワードを忘れると取り出せません。ファイルとパスワードは別々の場所に保管してください。
- 公式ウォレット側の動作（`child` が無いファイルを開いたときの扱いなど）は、アップロードされた公式ウォレットのソースを読んで合わせたもので、公式ウォレットのアプリ自体はこの環境では動かしていません。実機で一度、書き出したファイルを公式ウォレットで開いて確認してください。

### アカウントを削除したとき（完全に消去）
- 秘密鍵でインポートしたアカウント（.wlt から読み込んだものを含む）を「削除」すると、暗号化した秘密鍵・ハーベスト用の鍵に加えて、そのアカウントのIDで別保存していた設定（NEMのハーベストのノード、マルチシグのリモートアカウントの公開鍵）、ホームの表示キャッシュ、作りかけのアグリゲートもこの端末から消えます。
- プロファイルの削除とログアウトでは、上に加えて、そのプロファイルの「バックアップ済み」の印も消えます。パスワード（確認用ハッシュ）は、これまでどおり同時に消えます。
- 削除は元に戻せません。削除したあとでも、同じ .wlt ファイル（または秘密鍵）があれば、もう一度「秘密鍵でインポート」から読み込めます。
- アドレス帳の連絡先は、アカウントのデータではなくご自身の連絡先なので、消しません。
- 実装: `src/lib/accountPurge.ts`（`purgeAccountData`）。`WalletsHelper.removeImportedAccount` / `delete` / `deleteAll` から呼びます。テスト: `npx tsx dev-tests/account-purge.test.ts`

### ファイル
- `src/lib/nem/wlt.ts` … 作成（`buildWlt`）・読み取り（`parseWlt`）・パスワードで開く（`openWlt`）・ファイル名（`wltFilename`）。純粋関数
- `src/components/WltButton.tsx` … 書き出しのボタンとダイアログ
- `src/pages/account/AccountPage.tsx` … 秘密鍵を表示した下に書き出しボタン、「秘密鍵でインポート」に読み込みボタンとパスワード入力を追加（どちらも NEM のみ）
- `src/i18n/*.json` … `wallet.wlt_*`（日本語・英語・韓国語・中国語・ロシア語）
- `dev-tests/wlt.test.ts` … `npx tsx dev-tests/wlt.test.ts`（nem-sdk と同じ方法で作ったファイルとの相互確認を含む）

## マルチシグアカウントの委任ハーベスト (NEM)

公式 NEM Nano Wallet の「マルチシグアカウントの委任アカウントを管理」（`importanceTransfer` のマルチシグ版）と同じ機能です。連署者であるこのウォレットから、マルチシグアカウントの委任ハーベスト（重要性転送）を設定し、ノードにハーベストを任せます。マルチシグ画面（`/multisig`）の各アカウントの「委任ハーベスト」ボタン、またはハーベスト画面（`/harvest`）の案内から開きます（`/multisig/harvest`。`?account=アドレス` でアカウントを指定できます）。NEM のみ。閲覧用プロファイルと Ledger プロファイルでは出ません（パスワードで鍵を開いて署名するため）。

### 流れ
1. **リモートアカウントを有効化**: マルチシグアカウントの名義で重要性転送を送ります（マルチシグトランザクション。このウォレットがラッパーに署名し、手数料0.15 XEMを払います。内側の0.15 XEMはマルチシグアカウントが払います）。承認数が2以上のときは、ほかの連署者が「マルチシグ」画面の署名待ちで署名すると実行されます。実行から約6時間で有効になります。
2. **ハーベストを開始**: ノード（一覧または手入力。HTTPS のみ）を選び、リモートアカウントの秘密鍵をそのノードに渡します（通常のアカウントと同じ `/account/unlock`）。停止は `/account/lock`。
3. **無効化**: 有効になったあとでも、重要性転送で解除できます（ノードでの停止が先）。

### 画面
- 上に対象のマルチシグアカウントの選択（このウォレットが連署しているもの）。その下に状態（有効・有効化中・解除中・未設定）と残高。
- タブ: 「リモートアカウントの有効化」「ハーベストの開始」「状態」「委任鍵」「ハーベスト統計」（統計は通常のハーベストと同じブロック一覧。報酬はマルチシグアカウントに入ります）。
- 有効化には、マルチシグアカウントの有効残高が10,000 XEM以上であること、公開鍵がネットワークに出ていることが必要です。手数料に足りないときは警告を出します。

### リモートアカウント（NanoWallet と同じ）
リモートアカウントの秘密鍵は、**連署者の秘密鍵でマルチシグアカウントのアドレス（のSHA-256）に署名した結果の後ろ32バイト**です（NanoWallet の `generateData` と同じ式）。計算で決まるので保存せず、パスワードを確認したときに作ります。NanoWallet で有効化したものは、同じ連署者の鍵であればここでそのまま扱え、逆も同じです。

- リモートの**公開鍵だけ**をこの端末に覚えます（秘密ではない）。覚えていれば、パスワードなしでリモートのアドレスとノードでの状態を表示できます。未確認のときは「リモートアカウントを確認」（パスワード）を押します。秘密鍵は保存しません。
- リモートの鍵は連署者ごとに違います。有効なリモートアカウントが**自分の鍵から作ったもの**のときだけ、ハーベストの開始と無効化ができます（`/account/get/forwarded` で、そのリモートが誰のためにハーベストしているかを調べます）。別の連署者が有効化したものは、その連署者のウォレットで操作します。無効化は、送る直前にも調べ直します。
- 停止は、ノードが「動いている」と返すリモートアカウントならいつでも押せます（秘密鍵を渡すだけなので）。

### 署名待ちの表示
マルチシグ画面の署名待ちで、重要性転送は「委任ハーベストの設定」と出ます（有効化／無効化、リモートアカウントのアドレス）。ほかの連署者が、中身を知らずに署名するのを防ぐためです。取引履歴でも「重要性転送」として出ます。

### 委任鍵の表示
公式の「委任鍵を表示」と同じ値を出す「委任鍵」タブ。ノードにハーベストを任せるときに渡すリモートアカウントの鍵で、ふだんは「ハーベストの開始」が自動で渡すので、見る必要はありません。
- **アドレスと公開鍵**: 覚えていれば、パスワードなしで出ます。未確認のときは「秘密鍵を表示」か「リモートアカウントを確認」でパスワードを入れると出ます。
- **秘密鍵**: 「秘密鍵を表示（パスワード）」でパスワードを確認したときだけ、画面に出します。画面の中（コンポーネントの状態）にしか持たず、保存しません。次のどれかで自動的に隠れます: 「隠す」を押す／約1分たつ／別のタブへ移る／マルチシグアカウントを切り替える／アプリが背面に回る（別のタブ・画面ロックなど）／画面を離れる。
- 注意書きを画面に表示: 他人に見せない。この鍵ではXEMは送れないが、知っている人はこのアカウントのハーベストをノードに任せられる。写真・スクリーンショットを残さない。
- 値は公式と同じです（導出は上の「リモートアカウント」。公式 nem-sdk の秘密鍵と一致することをテストで確認）。表示は大文字の16進数（公式は小文字ですが、同じ値です）。
- 秘密鍵のコピー専用ボタンは付けていません（ウォレットのバックアップ画面と同じく、文字を選んでコピーします）。

### リモートアカウントの公開鍵を指定する（公式の「カスタムされた公開鍵を使用」）
「リモートアカウントの有効化」タブの「リモートアカウントの公開鍵を自分で指定する」をオンにすると、このウォレットが作るリモートアカウントの代わりに、**公開鍵（64文字の16進数）を入力して**重要性転送を送れます。状態が「未設定」または「有効」のときに出ます。
- **使いどころ**: ① 自分で用意したリモートアカウントを有効化する。② **別の連署者が有効化したリモートアカウントを引き継ぐ**。公式の説明のとおり、マルチシグでは重要性転送を実施した連署者だけがハーベストの開始・停止ができ、ほかの連署者が行うには Deactivate → Activate が要ります。引き継ぐ手順は次のとおりです。
  1. 有効化した連署者のウォレットの「委任鍵」タブで、リモートの公開鍵を確認して渡してもらう。
  2. 引き継ぐ連署者が、この画面で公開鍵を入力して「無効化」する（連署者の署名がそろい、状態が「未設定」に戻るのを待つ）。
  3. そのあと、このウォレットで通常どおり「有効化」する（約6時間後に有効）。
- **入力の検査**: 64文字の16進数（前後の空白・改行は無視、小文字も可）。マルチシグアカウント自身の公開鍵は不可。入力すると、その公開鍵のアドレスを表示します。
- **無効化のとき**: 入力した公開鍵が、このマルチシグアカウントの**有効なリモートアカウントであるか**を NIS（`/account/get/forwarded`）に確認し、確認できたときだけ「無効化」を押せます。送る直前にも確認し直し、違えば送らずに知らせます。
- **有効化のとき**: 公開鍵の形式と、有効残高10,000 XEM以上・手数料の残高を確認します。そのほかの条件（その公開鍵のアカウントを使ってよいか）は、ネットワークが送信時に判断します。
- **制限**: 公開鍵だけを入力するので、その秘密鍵を KASANE は持たず、**そのリモートアカウントでハーベストの開始・停止はできません**（確認のダイアログと説明に明記）。開始・停止ができるのは、このウォレットが作るリモートアカウントのときだけです。
- 手数料・署名の流れは、通常の有効化・無効化と同じです（確認ダイアログには、指定したリモートアカウントのアドレスを出します）。

### 公式と違うところ
- パスワードは KASANE 共通のパスワードダイアログ（入力回数の制限つき）で聞きます。
- 公式の画面にある「モード選択」（有効化／無効化のプルダウン）は、状態に合わせて出し分けています（未設定のときは有効化、有効のときは無効化のボタン）。
- 韓国語・中国語・ロシア語は英語で表示されます。

## NEM DNS（Domain Name System）

NEM Wallet（NanoWallet）の「DNS」（設定 `domainNameSystem` / 検索 `dnsSearch`）と**同じしくみ・互換**の機能です。**サービス > DNS**（`/dns`）。ネームスペースに、サイトのアドレスや連絡先を紐づけます。Symbol 版は下の「Symbol DNS」。

**しくみ（NanoWallet と同じ）**
- ネームスペース名（例 `kasane`。画面では `kasane.nem`）ごとに「ポインタアカウント」が決まる。秘密鍵 = Keccak-256( SHA-256( 名前のUTF-8 ) )（NanoWallet の `derivePassSha(SHA256(名前), 1)`）。鍵は名前から**だれでも計算できる**ので、ポインタアカウントには資産を送らない（画面でも注意する）。
- 登録 = ネームスペースの持ち主が、ポインタアカウントへ **0 XEM の送金**をする。メッセージ（平文）は `{"dns":"yes","ip1":"…","organization":"…","country":"…","address":"…","phone":"…","email":"…","other":"…"}`（空の項目は入れない）。値は JSON として正しくエスケープする（NanoWallet は引用符を逃がさないので、`"` を含む値で壊れる。KASANE の出力は NanoWallet でも読める）。
- 検索 = ポインタアカウントの送金履歴（新しい順、最大600件）から、**ネームスペースの持ち主が署名した**最初の DNS メッセージを探す。持ち主以外が送った DNS 形式のメッセージは無視する（偽の登録を防ぐ）。マルチシグ名義の送金も、その名義のアカウントが持ち主なら有効。

**検索タブ**
- ネームスペース名（`.nem` は付けても付けなくてもよい。大文字小文字は区別しない）を入れて「検索」（Enter でも可）。`?name=kasane` を付けて開くと、すぐ検索する。
- 表示: 持ち主・ポインタアカウント・登録内容（空でない項目だけ）・登録日時・登録トランザクション（エクスプローラーへのリンク）。ルートの期限が切れているときは、情報が古いかもしれない旨の注意を出す。
- 「サイトを開く」: NanoWallet は検索と同時に開くが、KASANE は結果を見てから**ボタンで開く**（ポップアップのブロックを避け、開く先を見せるため）。開けるのは http / https だけ（方式が無ければ `http://` を補う）。`javascript:` や、ユーザー名・パスワード入りのアドレスは開かない。新しいタブ、`noopener,noreferrer`。

**設定タブ**
- 登録するアカウント（自分／自分が連署するマルチシグ。Ledger のときは自分だけ）→ そのアカウントの有効なネームスペース → ポインタアカウント（読み取り専用）と、現在の登録内容の読み込み → 7項目を入力（サイトのアドレス・組織・国・住所・電話・メール・その他）。
- 残りバイト数（メッセージは1024バイトまで。NanoWallet は文字数で数えるが、KASANE はバイトで数える）。手数料は 0 XEM の送金として計算（マルチシグ名義は、署名の手数料 0.15 XEM が加わる）。
- 送信: パスワード（Ledger なら本体で確認）。マルチシグ名義は、連署が集まると記録される。承認（約1分）まで検索には出ない。
- 「ブロックチェーンに記録され、だれでも読める。個人情報は入れない」という注意を常に出す。更新は新しい内容を送ること（古い内容も履歴には残る）。

**NanoWallet との違い**
- 検索の名前から `.nem` を取るとき、NanoWallet は正規表現 `/.nem/g`（任意の1文字＋nem）で、`anem` のような名前まで壊す。KASANE は末尾の `.nem` だけを取る。
- NanoWallet は DNS 以外の自分のメッセージ（JSON でないもの）を読むと止まるが、KASANE は読み飛ばす。
- メッセージの16進は UTF-8 として戻す（NanoWallet は1バイトずつ文字にするので日本語が化ける）。

**ファイル**: `src/lib/nem/dns.ts`（名前・ポインタ鍵・メッセージ・履歴からの検索。SDK なし）／`src/lib/nem/dnsApi.ts`（ノードへの問い合わせ・登録）／`src/pages/nem/NemDns.tsx`／`router.tsx`・`ServiceHub.tsx`・`NavigationDrawer.tsx`・i18n 5言語（`nemdns.*`）

**テスト**
- `npx tsx dev-tests/nem-dns.test.ts` … SDK なし。ポインタの秘密鍵が NanoWallet（nem-sdk 本体を実際に動かして計算）と一致すること、名前の正規化、メッセージ、サイトのアドレス、偽の登録の無視、マルチシグ
- `npx tsx dev-tests/nem-dns-pointer.test.ts` … SDK。ポインタの公開鍵とアドレス（メインネット・テストネット）が NanoWallet と一致すること

## Symbol DNS（v229）

NEM の DNS（上）と**同じしくみ**を、Symbol のネームスペースに当てはめた機能です。**サービス > DNS**（`/dns`。Symbol でも同じ入り口。mijin v2 では「サービス」自体が出ません）。画面は検索タブと設定タブの2つで、NEM と同じ並び。

**しくみ（NEM と同じ。違いは下）**
- ネームスペース名（例 `kasane`、`company.team`）ごとに「ポインタアカウント」が決まる。秘密鍵は NEM と**同じ式**（Keccak-256( SHA-256( 名前のUTF-8 ) )。`nemDnsPointerPrivateKey` をそのまま使う）。この秘密鍵から Symbol の鍵（Ed25519 / SHA-512）でアドレスを作る。**同じ名前でも NEM と Symbol のポインタのアドレスは別物**で、メインネットとテストネットでも別。鍵は名前から**だれでも計算できる**ので、ポインタアカウントには資産を送らない（画面でも注意する）。
- 登録 = ネームスペースの持ち主が、ポインタアカウントへ**モザイクなしの送金**をする（かかるのは手数料だけ）。メッセージ（平文、先頭に種別バイト `00`）は NEM と同じ JSON `{"dns":"yes","ip1":"…","organization":"…","country":"…","address":"…","phone":"…","email":"…","other":"…"}`（空の項目は入れない）。JSON の組み立てと読み取りは NEM の `buildNemDnsMessage` / `parseNemDnsMessage` を共用するので、**NEM と Symbol で同じ書式**。
- 検索 = ポインタアカウントへの送金（新しい順、100件ずつ最大6ページ）から、**ネームスペースの持ち主が署名した**最初の DNS メッセージを探す。持ち主以外が送った DNS 形式のメッセージは無視する（偽の登録を防ぐ）。持ち主は、ネームスペースの情報（`GET /namespaces/{id}` の `ownerAddress`）から取る。
- **マルチシグが持ち主のとき**: 送金はアグリゲートの中の送金（署名者はマルチシグアカウント）として届く。通常の送金の一覧と、`embedded=true` の一覧（`meta.aggregateHash` があるものだけ使う）の両方を探し、それぞれの「最新」のうち、ブロックの高さ（同じなら順番）が新しい方を採る。

**NEM との違い**
- ネームスペース名: ルートも**64文字まで**（NEM は16文字）、深さは3まで。
- **「.nem」のような表示用の末尾は付けない**。Symbol では `foo.symbol` が「`foo` の下の子 `symbol`」のことがあり、末尾を取ると別の名前になってしまうため。入力は名前そのまま（大文字小文字は区別しない）。
- メッセージの上限は**1023バイト**（種別バイトを除く。送金の上限に合わせている。NEM は1024バイト）。
- 手数料は XYM。送金のサイズ（160＋1＋メッセージ）×手数料の倍率（設定の「手数料の既定値」の段階）。入力が止まって 300ms 後にノードに聞く。マルチシグ名義は、アグリゲートの手数料（連署の分の余白つき）。自分の署名だけで足りなければ bonded（ハッシュロックを預ける。承認されると返る）で、ほかの連署者がマルチシグの署名待ちの画面から署名する。NEM のような「外側の署名の手数料」は無い。
- 期限: `meta.active` と終了ブロック（ルート。子は親の期限に従う）から判断。切れていると注意を出す（持ち主が変わっているかもしれない）。
- 文言: Symbol 固有の8つだけ `symboldns.*`（about / search_about / search_hint / err_invalid_name / configure_about / pointer_hint / send_note / err_insufficient）、ほかは `nemdns.*` と、マルチシグの案内は `apostille.multisig_*` を共用（5言語）。

**設定タブ**
- 登録するアカウント（自分／自分が連署するマルチシグ。階層のあるマルチシグも。Ledger・閲覧用プロファイルでは自分だけ）→ そのアカウントの有効なネームスペース → ポインタアカウントと現在の登録内容 → 7項目を入力 → 手数料 → 送信（パスワード。Ledger は本体で確認。モザイクなしの送金なので Ledger でも署名できるが、マルチシグ名義は不可）。
- マルチシグは `planApproval` で、このアカウントが署名できるか（連署者か）・自分の署名だけで足りるかを判断する。署名できないときは送れない。

**ファイル**: `src/lib/symbol/dns.ts`（名前・メッセージの読み取り・履歴からの検索。SDK なし）／`src/lib/symbol/dnsApi.ts`（ポインタのアドレス・ノードへの問い合わせ・手数料・登録）／`src/pages/dns/SymbolDns.tsx`／`router.tsx`（`/dns` は `ByChain`）・`ServiceHub.tsx`（Symbol のタイルに追加）・i18n 5言語（`symboldns.*`）

**テスト**
- `npx tsx dev-tests/symbol-dns.test.ts` … SDK なし。名前の正規化、ポインタの秘密鍵（NEM と同じ）、メッセージの読み取り、履歴からの検索（持ち主以外・宛先違い・暗号化メッセージの無視、アグリゲートの中の送金、新しい方の選び方）
- `npx tsx dev-tests/symbol-dns-tx.test.ts` … SDK。ポインタのアドレス（メインネット N・テストネット T）、レコードを運ぶ送金（モザイクなし、種別バイト 00、サイズの見積もりとの一致）、1023バイトは通り1024バイトは断る、マルチシグのアグリゲートのサイズと bonded の手数料


## 投票（Voting）— Symbol

NEM の投票と同じしくみを Symbol に当てはめたもの。「サービス」→「投票」（`/voting`。mijin・閲覧用では非表示）。

- 投票は 0 XYM の送金メッセージでチェーンに書く。メッセージの形（`formData:` / `description:` / `options:` / `whitelist:` / `poll:`）は NEM と同じ JSON。
- アドレスは SHA3-256 の結果を「公開鍵」とみなして作る（投票 = 作成者の公開鍵 + タイトル、選択肢 = 投票のアドレス + 選択肢）。1 票 = 選択肢のアドレスへの空の 0 XYM 送金で、送り主ごとに数える。
- NEM との違い:
  - NEM の公式の公開インデックスに当たるものが Symbol にはないため、索引のアドレスを固定の文字列から作る（`POLL_INDEX_SEED`）。KASANE の Symbol 版の投票だけが載る（NEM Wallet の一覧とは別）。
  - 作成は 1 つのアグリゲート（完全）。全部入るか、全部入らないか。
  - 終了時刻は、取引のブロックの時刻で比べる。
  - 重要度は現在の値で重み付け（Symbol は過去の値を調べられない。終わった投票は、その旨を画面に出す）。
  - 1 メッセージの上限は 1023 バイト。アグリゲートの上限 100 件のため、ホワイトリストは約 2,200 アドレスまで。
- 数え方は NEM と同じ: 承認済み・終了前・モザイクなしの送金だけ。1 つだけ選べる投票では、複数に投票したアカウントの票は無効。
- 使えない: Ledger・閲覧用プロファイル（署名が要るため）。マルチシグ名義の投票は、NEM 版と同じく未対応（アグリゲートの中の他人の票は数える）。
- 実装: `src/lib/symbol/voting.ts`（判定ロジック・通信なし）、`votingApi.ts`（通信）、画面 `src/pages/voting/`、文言 `symbolvoting.*`（ほかは `nemvoting.*` を共用）。
- テスト: `npx tsx dev-tests/symbol-voting.test.ts`（2013項目）。
